# 上科大一图通

校园地图网页：旧版 2.5D 手绘底图 + 楼宇 + 点位动态管理 + 步行路网导航 + 活动雷达 + 食堂菜单，含两段**风雨长廊**和「雨天模式」导航。

## 功能

- **地图**：map.shanghaitech.edu.cn 的手绘瓦片（z14–19，已补画 11–13 号楼），百度墨卡托自定义 CRS 直接显示。
  拖动停在手绘画面的八边形边缘（避开侧栏 / 底部面板后计算），最多缩小到校园差不多铺满可见区域，最大 20 级
- **界面**（沿用 skdmap）：桌面左侧固定侧栏；手机顶部搜索 + 分类条，底部面板可拖动（收起 / 半屏 / 展开）。
  右侧按钮：隐藏地点名称、步行路网、回到全校、缩放
- **楼群**：物质学院 1–8、信息学院 1–3、学生公寓 1–13、教授公寓 1–6 号楼平时各合成一个标签（带栋数），
  点开（或点其中任意一栋）才显示每一栋的名字并用虚线圈出；放大到 19 级自动全部展开
- **地图标签**：按教学科研、住宿、餐饮、运动、生活服务、校门、风雨长廊、交通停车、活动分别显示或隐藏，支持一键全显／全隐；交通停车默认按需打开。隐藏的标签在悬停或选中时临时显示，离开或取消选中后恢复隐藏；悬停不触发全局避让，子标签出现时对应楼群标签隐藏。各类使用不同浅色实底，楼群同色加深一档，放大逐步展开；地点文字始终保持清晰，不随底图透明度淡化。
- **鼠标探索**：靠近标签时用边框、阴影和光泽提示，标签位置和命中框保持固定，悬停地点会点亮建筑并显示左下角预览；拖动、缩放或离开地图时复位，触屏保持静态，尊重系统减少动态效果设置。
- **标签避让**：选中地点与活动角标优先，楼群、主要地点和普通设施分层排布。被挡住的楼名隐藏，点位先收成图标；楼群可挪到组内相邻位置，并避开侧栏、地图工具和预览卡片。
- **楼宇**：65 个区域对象（含 5 个校门、2 段风雨长廊），点击查看分类、单位、别名、开放时间；医务室、校史馆、上海银行和耐思咖啡使用独立建筑轮廓。入口仅在主动查看或导航需要时展示；导航只标实际端点附近的入口。悬停仅临时高亮，移开后恢复，不改变已点击选中的对象；导航起终点通过点击确认。
- **地点去重**：建筑详情承接同名点位的内容，保留旧名搜索和旧链接。H1 / H2 分别显示校园服务中心 / 学生科创中心，体育场和运动场统一为操场。保留 17 个独立设施点，停车和车库口按需展示；同一餐厅的名称搜索只返回一个菜单入口。
- **风雨长廊**：地图上常亮（青色），点击有介绍；分类条里有「风雨长廊」
- **分类条**：食堂直接进入菜单，活动直接进入活动雷达；教学科研 / 住宿 / 风雨长廊 / 运动 / 服务 / 校门 / 停车显示分类目录。相关建筑在地图中批量选中：校徽红轮廓、淡色填充、完整显示原图和名称，其他建筑淡化；切换或取消分类后同步更新。活动场地随筛选联动。目录支持分类内搜索、楼群展开、简介、开放时间和活动角标；楼宇详情可按楼层查房间。
- **步行导航**：在数据包的步行栅格上跑 Dijkstra。起点 / 终点可以是楼、点位、地图上任意一点，选端点时搜索结果也直接当端点；
  有出入口的楼导到入口。「雨天模式」下露天路段按 2 倍代价算，路线会多走长廊下面（青色线段），并显示有多少米在长廊下
- **搜索**：楼群、楼名、简称、别名（一食堂、SIST…）、点位名，以及活动、餐厅、窗口和菜品；搜到活动或菜品可直接打开详情，选择导航端点时会使用举办地点或所在食堂
- **教室号搜索**：输入「1A-108」「SEM501」「图书馆302」「5-105」「S301」直接定位到楼和楼层，结果排在最前。先查 5 栋楼的房间表（551 间）；楼名或别名加号码、信息学院 `1A-108` / 物质学院 `5-105` 等编号规则按号码首位推测楼层；只看编号判断不了楼的（S301、M501）按往期活动地点推测。推测结果会注明。选中后详情顶部显示房间卡片，房间目录筛到该房间，地图楼名后显示房间号，导航终点也带上房间号
- **我的今天**：面板切换里的第四项。手动添加课程（可每周重复）、吃饭和待办，活动详情可「加入我的今天」；时间线按开始时间排列，两站之间显示步行分钟数（路网时间加 2 分钟进出楼），来不及时提示会迟到几分钟。今天有「下一项」卡片和建议出发时间。地图上按顺序给各站编号并画出步行路线。未登录时保存在本机浏览器，登录校园账号后同步到账号；浏览器禁止存储时提示刷新后会丢失
- **我的**：面板切换里的第五项，也是账号入口（登录后图标显示昵称首字）。集中管理校园账号与昵称、常用地点（寝室、实验室、办公室各一个，可填房间号；收藏地点若干）和课表（截图识别导入，可选择替换旧课表；手动添加、编辑、删除、清空）。课表按星期出现在「我的今天」，寝室和实验室出现在首页的一键导航。未登录时这些内容只存本机，登录后并入账号同步
- **智能建议**：午饭（11:00–13:30）和晚饭（16:30–19:00）在前后两站的空档里挑食堂：营业中、走过去加排队加走回下一站最省时间，空档够长时会晚点出发错开饭点高峰，并保证提前 5 分钟回到下一项；可一键加入安排。另外列出当天放得进空档、不冲突的活动。排队时间会优先使用最近 30 分钟的同学反馈，反馈不足时退回饭点高峰估算并标注来源
- **排队热力**：饭点打开食堂菜单或食堂详情，地图在各食堂周围显示按等级变化的热力圈；首页显示当前预计等待最短的食堂。食堂详情可反馈「不用排 / 排 5 分钟内 / 排很久」，同一匿名用户同一窗口 10 分钟内限报一次。实时反馈按 10 分钟半衰期聚合，超过 30 分钟没有实时数据时回退估算
- **实时定位**：右侧「定位」按钮显示蓝点、精度圈和朝向（iOS 点击时请求方向权限，拿不到时用行进方向），地图跟随，拖动地图后停止跟随、再点回到我的位置。手机 GPS（WGS-84）先转百度坐标，再用 `campus.json` 的 `warp`（175 个路口控制点，仿射 + 残差插值）落到手绘图上；不在校园边界内时只提示不显示。导航时起点可选「从我的位置出发」（已定位时打开导航会自动填上），边走边按当前位置重算路线，偏离超过 25 米提示重新规划，到终点 20 米内提醒已到达。浏览器只在 HTTPS 或 localhost 下给定位权限。演示用 `?mock`（或 `?mock=经度,纬度`）模拟定位：右键或长按地图换位置，导航卡片里可「模拟走一遍」
- **分享与扫码导航**：地点详情和活动详情的「分享」打开二维码框（前端用 `qrcode-generator` 生成），可复制链接、下载带标题的二维码图片，手机上还能调用系统分享。链接格式：`?to=<地点 id>&room=<房间号>` 打开后直接从我的位置导航，`?place=` 打开地点详情并定位房间，`?event=` 打开活动详情。首页底部「手机扫码使用」显示本站二维码；在 localhost 打开时会提示手机扫不开
- **地下车库设施**：停车点位可细分为车库坡道、车库楼梯、车库电梯（点位字段 `kind`），各用不同图标，详情注明用途，搜「车库楼梯」「地库」能找到。在后台点位表单选「停车」后出现「车库设施」下拉；换成其他分类会自动清除。现有 7 个「车库出入口」暂未细分，楼梯和电梯位置需要现场采集后在后台添加
- **活动雷达**：进行中 / 今天 / 近一周 / 全部待开始 / 往期，支持类型和地点筛选、分日列表、活动详情、原始通知、日历下载和链接分享；地图角标随筛选变化，地点详情显示后续活动
- **官网活动自动更新**：服务器每 2 小时从学校官网活动日历同步最近 60 天和未来 60 天的活动，按官网原始 `id` 去重，复用地点别名和教室号规则归并到地图；官网暂时删掉的活动保留并标记「已取消」，同步失败保留旧目录。后台「数据与备份」可查看最近同步时间及新增、更新、取消数量，并手动立即同步
- **活动地图钉**：地图常驻显示进行中和未来 24 小时内的活动（滚动窗口，可跨午夜），钉尖指向举办地点，上方标签显示时间和标题。越临近越醒目：进行中绿色带脉冲、一小时内开始橙色并倒数分钟、24 小时内紫色；跨天的展览等长期活动和更远的活动用淡色小钉。缩小时只留地图钉。点开某场活动后，地点上方弹出标注卡片（状态、标题、时间、房间、同地点场数）和红色地图钉，地点处有脉冲圈，其他活动淡化
- **活动时光机**（比赛展示用）：入口在管理后台顶栏「活动时光机」，选择「活动最多的 48 小时」「从现在开始」或指定开始时间（各显示收录场数），在新标签页打开前台全屏回放，侧栏收起，地图上自动播放 48 小时内的活动；也可复制链接。前台不显示入口。播放头经过时越临近开始的活动越醒目：钉子变大、颜色由淡紫转橙、地面光晕扩大，3 小时内挂出时间和标题；进行中绿色带脉冲，刚开始 30 分钟内弹出标注卡，结束后约 1 小时淡出，跨天展览只淡淡标出。「智能变速」在活动开始前后慢放、空档快进；「镜头跟随」飞到刚开始的活动再回到全校；底图按模拟时间昼夜渐变。底部时间轴可拖动，显示每场活动的时间条和「现在」位置；窗口可选「现在」「最热闹」（数据里活动最多的 48 小时）或前后按天切换，速度 0.5–4 小时/秒，可循环、全屏、扫码分享。点活动钉或右侧「此刻」卡片暂停并展开详情。快捷键：空格播放／暂停，←／→ 10 分钟（Shift 1 小时），Home 回到开头，Esc 退出。链接 `?timemachine`（`=best`、`=2026-05-19` 或 `=2026-05-19T08:00` 指定窗口起点）打开即自动播放
- **食堂菜单**：按食堂、楼层、窗口浏览 990 道菜；搜索菜名、窗口别名、口味和价格（如「15元以内的牛肉」），支持价格排序与供餐时段筛选；详情显示多规格价格、单位、照片、周菜单、菜单原图，可导航到食堂
- **食堂详情**：楼层切换、各餐次营业时间和停止点餐提醒；按周菜单日期、餐次、窗口筛选，展示窗口说明与菜品分组。菜品实拍和菜单原图支持页内放大、翻页与 Esc 关闭；从菜品详情返回保留筛选。

活动与菜单从 skdmap 迁入，首次启动从 `public/data/events.json`、`public/data/canteens.json` 的快照（2026-10-16）导入 SQLite，后续读取 `/api/events`、`/api/canteens`；服务不可用时回退到静态快照。活动目录随后由服务器定时调用学校官网活动日历接口更新；官网接口或地点转换失败时不清空旧数据。邮件活动仍由人工导入，活动人工修正保存在 `event_overrides` 后不会被自动同步覆盖。菜单照片继续使用 `public/photos/`，不调用 skdmap 服务。食堂营业状态按已收录时段计算，不代表实时库存；过期周菜单不计入「当前供餐」。静态离线副本可替换这两份 JSON 和引用的图片；数据库已初始化的目录不会被重启覆盖，后续目录更新应通过受控迁移同步 `discovery_catalog`。分享的活动链接带 `?event=<活动 ID>`，打开后直接显示详情。

后端挂了也能看地图和导航，楼宇与点位退回打包的静态数据（只读）。

## 独立管理后台

前台地址 `/`；后台地址 **`/admin/`**（开发时 http://localhost:5180/admin/）。
两个入口分别构建，使用独立页面、样式和状态。前台负责地图浏览、活动展示、菜单搜索和导航；旧 `#admin` 书签会跳转到新后台。

- **地点管理工作台**：统一管理建筑、区域与独立点位，取消重复的楼宇／点位顶栏页面。左侧目录支持类型、分类、名称、简称和别名筛选，中间地图定位，右侧查看或编辑；编辑时保留目录与地图上下文。新增、刷新收在目录顶部，工作区直接衔接导航栏。
- **新增地点**：选择「点位」或「建筑 / 区域」，查看对应用途和操作方式。点位在地图上点选位置，建筑逐点描绘范围；固定底部显示必填项状态、保存、取消，并支持「保存并继续新增」沿用分类录入下一项。
- **统一地图显示**：前台、地点管理与显示预览共用底图初始化和整数级缩放，避免小数缩放的瓦片白缝。管理地图同步已保存的透明度、羽化、分类标签样式与红色选中轮廓，并复用楼群分组和标签避让判断；编辑辅助点仅在调整时显示。
- **人工编辑**：基本信息、地图位置、补充信息分段呈现；拖动点位标记微调坐标，支持手动填写精确坐标和搜索别名。保存后原地查看最新详情，保留搜索筛选。
- **轮廓与入口**：拖动白色方点调整轮廓，点击边上的小圆点加点，选中顶点后删除；可新增、删除附属轮廓。出入口支持地图添加、命名和拖动，地图操作支持撤销 / 重做（⌘ / Ctrl Z、⌘ / Ctrl Shift Z）。
- **删除与保护**：详情和编辑区均提供删除入口，确认框列明地点名称及影响；删除失败可直接重试。切换地点或离开编辑前提示未保存修改，离线数据只读。
- **数据与备份**：查看分类分布、缺少出入口的建筑，导出全部建筑与点位 JSON 副本。
- **地图显示**：分别调整背景、可选对象、选中对象的透明度（0%–100%），用真实地图实时预览，支持恢复默认 20% / 50% / 100% 和撤销修改。边缘羽化保持开启；登录后保存到数据库，刷新前台生效。

浏览数据无需登录；点击编辑时验证管理口令，验证后直接继续原来的编辑。所有编辑先保留在草稿中，点击编辑栏底部「保存」（⌘ / Ctrl S）后才写入数据库，并显示已保存详情；目录和筛选保留；没有修改时直接返回，有未保存修改时提示确认。后台保存后，前台刷新即可读取更新。
后端不可用时显示静态数据并禁用写入。

## 运行

需要 Node ≥ 22.13（后端用内置 `node:sqlite`）。

```bash
npm install
```

开发（两个终端）：

```bash
npm run server
```

```bash
npm run dev
```

打开 http://localhost:5180 。后端在 8790 端口（避开 skdmap 的 8787 / 5173）。
生产：`npm start`（构建后由后端在 8790 端口同时提供网页和接口）。

**管理口令**：第一次启动后端会随机生成，写在 `server/.admin-password`（只有本机可读，已 gitignore）；
也可以启动前设 `ADMIN_PASSWORD=…`。楼宇和点位共同保存在 `server/map.db`。首次启动会从静态数据初始化；后续以数据库为准。现有点位数据库会自动增加楼宇表，保留已有点位修改。

测试：`npm run build && npm test`。覆盖导航、楼群，以及管理 API 的鉴权、点位与楼宇增删改、几何校验、重启持久化、空库不重复初始化、前后台独立入口。API 测试使用临时数据库和随机本地端口，不修改工作数据库。

## 数据

全部来自赛前数据包 `上科大智慧地图_赛前准备包/datapack`（坐标 BD-09，对齐手绘底图，见其中 `reference/projection.md`）。
`npm run data` 重新生成 `public/data/` 和 `public/tiles/`（默认读 `../上科大智慧地图_赛前准备包/datapack`，也可以把路径作为参数传进去）：

1. 两段风雨长廊（后台人工描的轮廓）加上 `walkway: true`，并把原来那个近似位置的「风雨长廊」点位删掉、介绍挪到轮廓上
2. 只保留校园边界内的点位（校外公交站、地铁口、周边商场不要）
3. 复制瓦片
4. 应用 `data/building-outline-refinements.json` 中逐栋核对的轮廓修正，重新生成数据时保留修正结果；如果源数据里的同一轮廓已被另外修改，则停止并报告冲突
5. 应用 `data/construction-outline-refinements.json` 的两处在建用地边界，以及 `data/place-curation.json` 的地点归属和去重记录

2026-10-16 核对原有 61 个区域对象，并将 4 个有独立楼体的点位升级为建筑，共 65 个。边界沿手绘图可见的屋顶和立面，排除地面阴影；11–13 号楼按前后遮挡拆开，操场跑道和看台用独立轮廓表示。医务室对应服务中心最北侧楼体，校史馆对应三栋红顶小楼的中间一栋。耐思咖啡对应学生公寓1号楼最左侧临路灰顶小楼，学生活动中心对应右侧连接体，上海银行对应道路另一侧白顶楼；肯德基位于3号楼西侧小楼。两处在建区域按可见用地边界勾选，保留在建提示。

已有数据库不会随静态数据自动覆盖。先运行 `node scripts/apply-building-outlines.mjs`，再运行 `node scripts/apply-place-curation.mjs` 预览，分别加 `--write` 写入（可在命令后指定数据库路径）。第一步更新轮廓和标签中心，第二步合并 12 个重复点位、将 4 个点位升级为建筑，并同步菜单目录的位置和搜索别名。写入前完整备份所改表到数据库旁的 `backups/`，整批使用事务，保留现有菜单、价格及其他资料；遇到后续人工修改则报告冲突。重复执行不会重复写入，也不会恢复已删除记录。修正清单保留原始及早期已校对版本，支持从原始数据或已整理过的版本继续迁移。

`poly` 表示主体轮廓，`parts` 表示不相连的附属轮廓（例如看台、第二块在建用地），不会把中间的道路或草地填满。前台选中、透明度遮罩、范围定位及后台逐部分编辑均使用完整轮廓。

楼宇和点位初始化之后以 `server/map.db` 为准，重新跑 `npm run data` 不会覆盖已有修改。删除全部记录后重启也不会恢复已删除内容。

## 科大 · 同频：活动与档口交流

每场活动详情、每个档口菜单标题、菜品详情，以及每个楼宇和点位的详情（理发店、图书馆自习区、办事窗口等，校门和风雨长廊除外）均可进入独立交流区。地点交流区在第一次访问时按需创建，确认楼宇或点位存在后才建，名称和资料随后台修改同步；地点删除后已有讨论仍可查看。支持图文笔记（最多 4 张图片）、分享／提问／测评／攻略／约伴标签、评论与回复、点赞、收藏、搜索，以及最新／热门／我的收藏筛选。桌面为宽屏弹窗，手机为全屏双列卡片。

首次访问会生成一个匿名会话，只用于浏览、点赞、收藏和排队反馈，不对外显示名字。会话由 HttpOnly、SameSite Cookie 保存一年；浏览和查看总结无需登录，但发布笔记、评论、图片和签到必须先用 `@shanghaitech.edu.cn` 校内邮箱验证码登录。公开署名用的昵称绑定在校园账号上：新账号首次登录时起昵称，之后在「我的」里修改，换设备登录还是同一个昵称；没起昵称的账号不能发笔记和评论。登录会把当前匿名会话里的内容迁移到校园账号，换设备后个人数据通过 `/api/me/data` 同步；登出后会换发新的匿名会话。所有帖子、评论、点赞、收藏、身份、图片 BLOB 和 AI 总结均保存在 `server/map.db`，不是 localStorage。删除笔记会级联删除图片、评论、互动和对应旧总结。

### 校园账号、活动和课表识别

复制 `.env.example` 到 `.env` 后配置 `SMTP_URL` 与 `MAIL_FROM` 即可发送登录验证码；`DEMO_MODE=true` 时验证码打印在后端日志，并额外允许 `@demo.test` 演示账号。主办方在 `/admin/` 的「活动」页登录后可以创建活动、选择地点并生成带 `?event=` 二维码的海报，账号需要 `organizer` 或 `admin` 角色。课表截图通过 `/api/schedule/parse` 发给 DeepSeek V4.1，默认模型为 `deepseek-v4.1`，密钥只从服务端的 `SCHEDULE_VISION_API_KEY`（或兼容的 `DEEPSEEK_API_KEY`）读取，地址可用 `SCHEDULE_VISION_BASE_URL` 覆盖。

### DeepSeek 配置

复制 `.env.example` 到项目根目录 `.env`，填写 `DEEPSEEK_API_KEY`，再启动／重启 `npm run server`。已有环境变量优先于文件。`.env` 已忽略，**不要使用 `VITE_` 前缀**，不要提交密钥。模型可通过 `DEEPSEEK_MODEL` 配置，默认 `deepseek-flash`；实现遵循 [DeepSeek 官方 Chat API](https://api-docs.deepseek.com/) 和 [JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/)。

AI 请求由服务器发往 `https://api.deepseek.com/chat/completions`，前端只访问本站接口。点击生成才调用；发送活动／档口已收录资料、最新最多 40 篇笔记（每篇正文最多 600 字）、最新最多 80 条评论（每条最多 180 字），不发送昵称、身份凭据或图片。返回概览、重点和待确认问题；页面显示采样数量、生成时间、AI 提示。无讨论时明确说明暂无同学反馈，不生成虚构评价。资料、帖子或评论变化后标记旧总结待更新，删除内容即清除旧总结。同一资料版本复用数据库缓存，并合并同一交流区并发请求。

内置 45 秒请求超时、失败重试入口、缺少密钥／余额不足／无效密钥／服务繁忙提示。单 IP 每分钟最多 6 次新总结，全站每小时最多 60 次（计数持久化），同时最多 3 个生成任务。帖子、评论、上传另有限流。图片在浏览器缩至最长边 1400px、转成 JPEG（移除原图 EXIF 信息），后端限制每张 2MB，仅接受 JPEG／PNG／WebP。未发布图片 24 小时后在下一次上传时清理。

部署时持久化并备份 `server/map.db`（运行中的 SQLite 请使用 backup API 或连同 WAL 一致备份）。HTTPS 反向代理部署设置 `COOKIE_SECURE=true`，转发原始 Host，让社区同源检查正确工作。开发代理已配置保留 Host。接口不开放跨站 CORS，写请求需要 `X-Community-Request: 1` 与同源 Origin（若浏览器提供）。
