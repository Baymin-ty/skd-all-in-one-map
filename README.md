# 上科大一图通

上科大校园地图与校园信息工具：手绘地图、楼宇与点位、步行导航、活动雷达、食堂菜单、校园账号、我的今天和「科大 · 同频」交流区。导航统一按距离计算，后台可以维护地上地点与地下路网、遮雨路网、活动与讨论、食堂菜品。

## 功能简介

- **找得到**：按楼宇、楼群、地点、教室号、活动、食堂、窗口和菜品搜索；打开结果即可查看详情、楼层房间和地图位置。
- **走得到**：支持楼宇入口、任意地图点和「我的位置」作为导航端点；步行路网统一处理手绘道路与补充道路，按距离计算。
- **安排得好**：活动雷达、食堂营业与排队热力、我的今天、课表导入、常用地点和智能用餐建议放在同一张校园地图上。
- **一起维护**：管理员可以编辑地点、轮廓、出入口、地下路网和食堂菜品；活动从官网与通知邮件自动更新，后台可修改、置顶、隐藏，异常条目进入审核队列；同学可以在活动、档口、菜品和地点下交流，后台可删除不合适的内容。

完整的面向使用者说明见 [功能介绍](docs/功能介绍.md)。

## 功能

- **地图**：map.shanghaitech.edu.cn 的手绘瓦片（z14–19，已补画 11–13 号楼），百度墨卡托自定义 CRS 直接显示。
  拖动停在手绘画面的八边形边缘（避开侧栏 / 底部面板后计算），最多缩小到校园差不多铺满可见区域，最大 20 级
- **界面**（沿用 skdmap）：桌面左侧导航栏放地图 / 活动 / 美食 / 日程 / 我的，下面是导航和快递站；手机顶部搜索框右侧是导航按钮。分类条桌面浮在地图左上角，手机在搜索框下面；地图右侧按钮列最上面是「全校」开关（有我的地图时才出现）。首页面板只放最重要的：我的地图是「接下来」和今天 / 明天 / 本周的安排（日期在面板里选），全校地图是食堂排队，没登录时最上面是登录邀请，从我的地图切过来时是「回到我的地图」和「接下来」；完整日程在「日程」，课表和常用地点在「我的」，底部面板可拖动（收起 / 半屏 / 展开）。
  右侧按钮：图层与标签、定位、缩放。打开页面时就申请定位，只显示蓝点、不移动地图；最小缩放让校园差不多铺满可见区域
- **我的地图**：登录了或这台设备上导入过课表时，每次打开默认显示自己的地图；否则默认全校地图。全校地图用地图右侧的「全校」按钮临时打开，再点一次或点面板里的「回到我的地图」回去，上次看哪张不记。只突出今天 / 明天 / 本周有安排的地点：
  每处插一面小旗写着时间和标题，课程蓝、活动橙红、吃饭琥珀、待办灰蓝，正在进行和下一项填满颜色，同一地点多项合成一面（+N）；
  某一天按时间顺序画出各站之间的步行路线。寝室、实验室、收藏单独标出；其他地点淡下去、小设施图标收起，全校活动只在全校地图和活动雷达里显示。
  点小旗打开那栋楼并定位到教室（活动打开活动详情）。面板最上面是「接下来」卡片（从上一站或寝室步行几分钟、几点出发、一键导航），
  下面是按类型区分的日程列表和常用地点。每次打开、登录或退出时按身份重新决定默认看哪张图，不沿用上次手动切换的结果
- **手机端**：竖屏打开时按可见区域高度铺满校园（左右可拖），标签收紧一档；面板收起时露出一张卡片（我的地图是「接下来」，全校地图是登录邀请或「接下来」）。
  面板没展开时在内容上竖着滑就是拉面板，展开后列表滚到顶再下滑收回；顶部栏和底部标签栏按刘海、Home 指示条的安全区实际测量
- **楼群**：物质学院 1–8、信息学院 1–3、学生公寓 1–13、教授公寓 1–6 号楼平时各合成一个标签（带栋数），
  点开（或点其中任意一栋）才显示每一栋的名字并用虚线圈出；放大到 19 级自动全部展开
- **地图标签**：图层面板按教学科研、餐饮、运动、校门、生活服务、住宿分别显示或隐藏，支持一键全显／全隐；默认不显示住宿和生活服务。停车点不进面板，只在悬停、选中、筛选或导航用到时显示标签。隐藏的标签在悬停或选中时临时显示，离开或取消选中后恢复隐藏；悬停不触发全局避让，子标签出现时对应楼群标签隐藏。各类使用不同浅色实底，楼群同色加深一档，放大逐步展开；地点文字始终保持清晰，不随底图透明度淡化。
- **鼠标探索**：靠近标签时用边框、阴影和光泽提示，标签位置和命中框保持固定，悬停地点会点亮建筑；拖动、缩放或离开地图时复位，触屏保持静态，尊重系统减少动态效果设置。
- **标签避让**：选中地点与活动角标优先，楼群、主要地点和普通设施分层排布。被挡住的楼名隐藏，点位先收成图标；楼群可挪到组内相邻位置，并避开侧栏和地图工具。
- **楼宇**：65 个区域对象（含 5 个校门、2 段风雨长廊），点击查看分类、单位、别名、开放时间；医务室、校史馆、上海银行和耐思咖啡使用独立建筑轮廓。入口仅在主动查看或导航需要时展示；导航只标实际端点附近的入口。悬停仅临时高亮，移开后恢复，不改变已点击选中的对象；导航起终点通过点击确认。
- **地点去重**：建筑详情承接同名点位的内容，保留旧名搜索和旧链接。H1 / H2 分别显示校园服务中心 / 学生科创中心，体育场和运动场统一为操场。保留 17 个独立设施点，停车和车库口按需展示；同一餐厅的名称搜索只返回一个菜单入口。
- **风雨长廊**：作为普通区域保留实际轮廓，点击有介绍；不再有专属图层，导航也不因它改变路线
- **分类条**：食堂直接进入菜单，活动直接进入活动雷达；教学科研 / 住宿 / 运动 / 服务 / 校门显示分类目录。相关建筑在地图中批量选中：校徽红轮廓、淡色填充、完整显示原图和名称，其他建筑淡化；切换或取消分类后同步更新。活动场地随筛选联动。目录支持分类内搜索、楼群展开、简介、开放时间和活动角标；楼宇详情可按楼层查房间。
- **统一步行路网与导航**：构建阶段将手绘道路和 OSM 补充道路合并成一张步行栅格，运行时只按可走 / 不可走处理，不再按来源区分颜色或额外加价。起点 / 终点可以是楼、点位、地图上任意一点，选端点时搜索结果也直接当端点；有出入口的楼导到入口。
  按实际路径长度比较地面直达与一次「地面 → 地下 → 地面」候选，不设天气权重或进出地下附加代价。蓝色表示地面，紫色表示地下，并显示进出连接点。沿用栅格 Dijkstra、吸附与拉直及原有候选枚举，不保证多次进出地下的全局最短路线；地下入口仍是原有手绘/后台维护入口。
- **搜索**：楼群、楼名、简称、别名（一食堂、SIST…）、点位名，以及活动、餐厅、窗口和菜品；搜到活动或菜品可直接打开详情，选择导航端点时会使用举办地点或所在食堂
- **教室号搜索**：输入「1A-108」「SEM501」「图书馆302」「5-105」「S301」直接定位到楼和楼层，结果排在最前。先查 5 栋楼的房间表（551 间）；楼名或别名加号码、信息学院 `1A-108` / 物质学院 `5-105` 等编号规则按号码首位推测楼层；只看编号判断不了楼的（S301、M501）按往期活动地点推测。推测结果会注明。选中后详情顶部显示房间卡片，房间目录筛到该房间，地图楼名后显示房间号，导航终点也带上房间号
- **我的今天**：面板切换里的第四项（标签栏里叫「日程」）。手动添加课程（可每周重复）、吃饭和待办，活动详情可「加入我的今天」；时间线按开始时间排列，两站之间显示步行分钟数（路网时间加 2 分钟进出楼），来不及时提示会迟到几分钟。今天有「下一项」卡片和建议出发时间。地图上用和我的地图一样的小旗标出各站并画出步行路线。未登录时保存在本机浏览器，登录校园账号后同步到账号；浏览器禁止存储时提示刷新后会丢失
- **我的**：面板切换里的第五项，也是账号入口（登录后图标显示昵称首字）。集中管理校园账号与昵称、常用地点（寝室、实验室、办公室各一个，可填房间号；收藏地点若干）和课表（截图识别导入，可选择替换旧课表；手动添加、编辑、删除、清空）。课表按星期出现在「我的今天」，寝室和实验室出现在首页的一键导航。未登录时这些内容只存本机，登录后并入账号同步
- **智能建议**：午饭（11:00–13:30）和晚饭（16:30–19:00）在前后两站的空档里挑食堂：营业中、走过去加排队加走回下一站最省时间，空档够长时会晚点出发错开饭点高峰，并保证提前 5 分钟回到下一项；可一键加入安排。另外列出当天放得进空档、不冲突的活动。排队时间会优先使用最近 30 分钟的同学反馈，反馈不足时退回饭点高峰估算并标注来源
- **排队热力**：饭点打开食堂菜单或食堂详情，地图在各食堂周围显示按等级变化的热力圈；首页显示当前预计等待最短的食堂。食堂详情可反馈「不用排 / 排 5 分钟内 / 排很久」，同一匿名用户同一窗口 10 分钟内限报一次。实时反馈按 10 分钟半衰期聚合，超过 30 分钟没有实时数据时回退估算
- **实时定位**：右侧「定位」按钮显示蓝点、精度圈和朝向（iOS 点击时请求方向权限，拿不到时用行进方向），地图跟随，拖动地图后停止跟随、再点回到我的位置。手机 GPS（WGS-84）先转百度坐标，再用 `campus.json` 的 `warp`（175 个路口控制点，仿射 + 残差插值）落到手绘图上；不在校园边界内时只提示不显示。导航时起点可选「从我的位置出发」（已定位时打开导航会自动填上），边走边按当前位置重算路线，偏离超过 25 米提示重新规划，到终点 20 米内提醒已到达。浏览器只在 HTTPS 或 localhost 下给定位权限。演示用 `?mock`（或 `?mock=经度,纬度`）模拟定位：右键或长按地图换位置，导航卡片里可「模拟走一遍」
- **分享与扫码导航**：地点详情和活动详情的「分享」打开二维码框（前端用 `qrcode-generator` 生成），可复制链接、下载带标题的二维码图片，手机上还能调用系统分享。链接格式：`?to=<地点 id>&room=<房间号>` 打开后直接从我的位置导航，`?place=` 打开地点详情并定位房间，`?event=` 打开活动详情。首页底部「手机扫码使用」显示本站二维码；在 localhost 打开时会提示手机扫不开
- **地下车库设施**：停车点位可细分为车库坡道、车库楼梯、车库电梯（点位字段 `kind`），各用不同图标，详情注明用途，搜「车库楼梯」「地库」能找到。在后台点位表单选「停车」后出现「车库设施」下拉；换成其他分类会自动清除。现有 7 个「车库出入口」暂未细分，楼梯和电梯位置需要现场采集后在后台添加
- **地下路网与标注**：`public/data/underground.json` 使用 version 2，包含 32 个节点、33 条双向边、16 个上下连接点及 6 张参考图纸。道路只保存节点坐标与连接关系，每条边恰好引用两个不同节点，不保存 path/mode/direction/source/note，也没有模式筛选。导航直接沿显式边寻路，不自动接通相邻或交叉的孤立道路；未绑定连接点在 45 米内临时投影接入，持久化坐标不变。后台支持连接点独立放置、显式绑定、解绑、删除与撤销，保留类型、楼层、说明和街景点端点权重。街景点只保存随机 GUID 和两个路网端点的插值权重；图片文件放在 `data/streetview/<GUID>.<jpg|png|webp|avif>`，后台可直接上传并自动按 GUID 改名，通过 `/streetview/<GUID>` 读取
- **活动雷达**：进行中 / 今天 / 近一周 / 全部待开始 / 往期，支持类型和地点筛选、分日列表、活动详情、原始通知、日历下载和链接分享；地图角标随筛选变化，地点详情显示后续活动
- **活动数据管道与审核**：服务器每 2 小时从学校官网活动日历同步最近 60 天和未来 60 天的活动；配置 IMAP 后每 30 分钟读取学校通知邮件。两类来源按稳定 ID、标题、日期和时间去重，地点复用别名与教室号规则归并到地图；无法确认的条目进入后台「待审核」，管理员可编辑后通过或拒绝。官网暂时删掉的活动保留并标记「已取消」，同步失败保留旧目录。
- **活动地图钉**：地图常驻显示进行中和未来 24 小时内的活动（滚动窗口，可跨午夜），钉尖指向举办地点，上方标签显示时间和标题。越临近越醒目：进行中绿色带脉冲、一小时内开始橙色并倒数分钟、24 小时内紫色；跨天的展览等长期活动和更远的活动用淡色小钉。缩小时只留地图钉。点开某场活动后，地点上方弹出标注卡片（状态、标题、时间、房间、同地点场数）和红色地图钉，地点处有脉冲圈，其他活动淡化
- **活动时光机**（比赛展示用）：入口在管理后台顶栏「活动时光机」，选择「活动最多的 48 小时」「从现在开始」或指定开始时间（各显示收录场数），在新标签页打开前台全屏回放，侧栏收起，地图上自动播放 48 小时内的活动；也可复制链接。前台不显示入口。播放头经过时越临近开始的活动越醒目：钉子变大、颜色由淡紫转橙、地面光晕扩大，3 小时内挂出时间和标题；进行中绿色带脉冲，刚开始 30 分钟内弹出标注卡，结束后约 1 小时淡出，跨天展览只淡淡标出。「智能变速」在活动开始前后慢放、空档快进；「镜头跟随」飞到刚开始的活动再回到全校；底图按模拟时间昼夜渐变。底部时间轴可拖动，显示每场活动的时间条和「现在」位置；窗口可选「现在」「最热闹」（数据里活动最多的 48 小时）或前后按天切换，速度 0.5–4 小时/秒，可循环、全屏、扫码分享。点活动钉或右侧「此刻」卡片暂停并展开详情。快捷键：空格播放／暂停，←／→ 10 分钟（Shift 1 小时），Home 回到开头，Esc 退出。链接 `?timemachine`（`=best`、`=2026-05-19` 或 `=2026-05-19T08:00` 指定窗口起点）打开即自动播放
- **食堂菜单**：按食堂、楼层、窗口浏览 990 道菜；搜索菜名、窗口别名、口味和价格（如「15元以内的牛肉」），支持价格排序与供餐时段筛选；详情显示多规格价格、单位、照片、周菜单、菜单原图，可导航到食堂
- **食堂详情**：楼层切换、各餐次营业时间和停止点餐提醒；按周菜单日期、餐次、窗口筛选，展示窗口说明与菜品分组。菜品实拍和菜单原图支持页内放大、翻页与 Esc 关闭；从菜品详情返回保留筛选。
- **科大 · 同频**：活动、档口、菜品和地点详情可进入独立交流区，支持图文笔记、评论与回复、点赞、收藏、搜索和基于已收录资料的 AI 总结；校园账号昵称用于公开署名，匿名会话只用于浏览、互动和排队反馈。

活动与菜单从 skdmap 迁入，首次启动从 `public/data/events.json`、`public/data/canteens.json` 的快照（2026-10-16）导入 SQLite，后续读取 `/api/events`、`/api/canteens`；服务不可用时回退到静态快照。活动目录由官网活动日历和可选的 IMAP 通知邮件数据源更新；官网接口、邮箱连接或地点转换失败时不清空旧数据。邮件中的可疑活动进入 `event_review` 待审核队列，管理员确认后才上线；人工修正保存在活动记录的 `manualOverrides` 中，不会被自动同步覆盖。菜单照片继续使用 `public/photos/`，不调用 skdmap 服务。食堂营业状态按已收录时段计算，不代表实时库存；过期周菜单不计入「当前供餐」。静态离线副本可替换这两份 JSON 和引用的图片；数据库已初始化的目录不会被重启覆盖，后续目录更新应通过受控迁移同步 `discovery_catalog`。分享的活动链接带 `?event=<活动 ID>`，打开后直接显示详情。

后端挂了也能看地图和导航，楼宇与点位退回打包的静态数据（只读）。

## 独立管理后台

前台地址 `/`；后台地址 **`/admin/`**（开发时 http://localhost:5180/admin/）。
两个入口分别构建，使用独立页面、样式和状态。前台负责地图浏览、活动展示、菜单搜索和导航；旧 `#admin` 书签会跳转到新后台。

- **地图数据（地上 / 地下）**：顶栏只有一个「地图数据」入口，目录左上角切换地上和地下两层。两层使用同一套布局：左侧目录（地上是建筑与点位，地下是路网统计、连通性检查、出入口和图片点），中间地图，右侧在选中对象时展开详情或编辑。地上地点支持类型、分类、名称、简称和别名筛选；地下路网保留道路、出入口、图片点、删除工具和快捷键，先进入草稿，点「保存」后写入。
- **新增地点**：选择「点位」或「建筑 / 区域」，查看对应用途和操作方式。点位在地图上点选位置，建筑逐点描绘范围；固定底部显示必填项状态、保存、取消，并支持「保存并继续新增」沿用分类录入下一项。
- **统一地图显示**：前台与地点管理共用底图初始化和整数级缩放，避免小数缩放的瓦片白缝。三层透明度（背景 64%、可选对象 100%、选中对象 100%）是固定配置 `public/data/map-settings.json`，前台和后台直接读取，修改后重新构建生效；管理地图同样复用羽化、分类标签样式、红色选中轮廓、楼群分组和标签避让。
- **人工编辑**：基本信息、地图位置、补充信息分段呈现；拖动点位标记微调坐标，支持手动填写精确坐标和搜索别名。保存后原地查看最新详情，保留搜索筛选。
- **轮廓与入口**：拖动白色方点调整轮廓，点击边上的小圆点加点，选中顶点后删除；可新增、删除附属轮廓。出入口支持地图添加、命名和拖动，地图操作支持撤销 / 重做（⌘ / Ctrl Z、⌘ / Ctrl Shift Z）。
- **删除与保护**：详情和编辑区均提供删除入口，确认框列明地点名称及影响；删除失败可直接重试。切换地点或离开编辑前提示未保存修改，离线数据只读。
- **活动管理**：「活动目录」按未结束 / 往期、来源、状态（隐藏、取消、人工改过、有讨论）筛选全部活动，可修改时间地点等字段、置顶并调整置顶顺序（前台活动列表最先显示）、在前台隐藏、标记取消、生成海报和签到码，后台新建的活动可删除。官网和邮件同步来的活动改过的字段记入 `manualOverrides`，之后同步不会覆盖。「待审核」处理可疑条目；「讨论管理」按活动 / 档口 / 地点查看同学笔记、图片和评论并删除不合适的内容；「数据来源」查看官网与邮件抓取状态、运行记录，并可立即抓取。
- **菜品管理**：按食堂 → 楼层 / 窗口区 → 档口浏览菜单，新增、修改、删除菜品：菜名、分组、价格与多规格、计价单位、供应餐次、标签、介绍、照片和待核对备注；列表里一键切换售罄。周菜单日期和数据来源由导入脚本维护，后台保留原值。
- **数据与备份**：服务运行时间、数据库大小、活动最近更新和待审核数；地上、地下、活动、菜单、同学互动的数据规模；管理口令、自动更新、邮件、AI 总结等关键配置是否就绪和地图显示配置；导出地上地点、地下路网、活动目录、食堂菜单 JSON 副本，列出待补充出入口和服务器备份文件。

浏览数据无需登录；点击编辑时验证管理口令，验证后直接继续原来的编辑。所有编辑先保留在草稿中，点击编辑栏底部「保存」（⌘ / Ctrl S）后才写入数据库，并显示已保存详情；目录和筛选保留；没有修改时直接返回，有未保存修改时提示确认。后台保存后，前台刷新即可读取更新。
后端不可用时显示静态数据并禁用写入。

### 地下图 version 2 与一次性迁移

地下整图结构如下（连接点 `node` 可选，未绑定时保持独立 `pos`）：

```json
{
  "version": 2,
  "floor": -1,
  "bounds": [[121.5955, 31.1808], [121.6062, 31.1865]],
  "sources": [],
  "nodes": [{ "id": "n1", "pos": [121.6, 31.184] }, { "id": "n2", "pos": [121.601, 31.184] }],
  "edges": [{ "id": "e1", "a": "n1", "b": "n2" }],
  "connectors": [{ "id": "c1", "kind": "stairs", "floorFrom": 0, "floorTo": -1, "pos": [121.6, 31.184], "node": "n1", "note": "楼梯说明" }],
  "points": [{ "id": "p1", "endpointId1": "n1", "endpointWeight1": 0.5, "endpointId2": "n2", "endpointWeight2": 0.5, "imageId": "photo1" }]
}
```

`PUT /api/underground` 严格拒绝旧格式、额外节点/边属性、无效引用、自环、重复无向边和重复对象 ID。`sources` 的图片、锚点和说明保持原协议。编辑器直接往返节点与边 ID，不合并二度折点。草稿导入按几何位置复用节点，识别已经分割的直线并去重无向边；成功保存后只消费本次实际保存的本机草稿，保留新草稿和未完成线段，无需道路 source 标记。

运行时不转换 v1。部署前由操作者对指定的 static 库执行一次性迁移；脚本没有默认目标，不会由服务启动自动调用。先停止会写入该库的旧服务，再预览和写入，最后部署启动新服务。不要迁移历史 `map.db` 或 `backups`。

```bash
# 只读预览，不产生备份或修改
node scripts/migrate-underground-graph.mjs --db C:/path/to/static.db
# 写入指定库，可选备份原始 default 行（JSON，包含 updated_at）
node scripts/migrate-underground-graph.mjs --db C:/path/to/static.db --write --backup C:/path/to/underground-v1-row.json
# 静态 JSON 可单独预览/转换；仓库静态文件已转为 v2
node scripts/migrate-underground-graph.mjs --json public/data/underground.json
node scripts/migrate-underground-graph.mjs --json C:/path/to/underground.json --write --backup C:/path/to/underground-v1.json
```

备份参数可省略，指定时目标必须为新文件；数据库备份是该行原始 JSON 和时间戳，不是全库副本。数据库转换在事务中完成，只更新 `underground_maps` 的 `default` 行。折线的每个折点变成节点，不同道路相同坐标共用节点，去掉自环和重复无向边，忽略旧道路属性。已有节点 ID（包括同坐标的既有别名节点）和街景点引用保留；只有旧连接点精确落在节点上时恢复绑定，其他连接点不移动。重复执行 v2 不改写。

### SQLite 存储与第一阶段拆库

- `server/static.db`：仅存 `buildings`、`pois`、独立的 `underground_maps` 地下整图表和地图 `meta` keys（`pois.seeded`、`buildings.seeded`、`map.settings`）。地下路网保持一条 `id='default'` 的完整 version 2 JSON，nodes/edges 不拆表；首次空库从静态 JSON 初始化，之后以数据库为准，清空后重启不会恢复记录。仅此数据库允许纳入 Git；提交前仍需核查内容。
- `server/dynamic.db`：社区、账号、活动、菜单等其余业务表及非地图 `meta`；包含敏感数据，不入 Git。旧 `server/map.db` 同样不入 Git。
- 默认启动时，若 dynamic 尚不存在，`server/databases.mjs` 用 SQLite online backup 从旧 `map.db` 读取一致性快照（含已提交 WAL），先写同目录临时文件，完整关闭后再原子发布。旧源不执行写入、不删除；禁止手工只复制运行库主文件。
- dynamic 中地图数据在首次创建 static 时以事务复制；static 完整发布并成功打开后，才在 dynamic 事务内删除地图表和地图 keys。启动迁移会把旧 `meta` 的 `underground.map` 先成功写入 `underground_maps(id='default', data, updated_at)`，再删除旧 key；已有目标行优先、不被旧值覆盖，失败可重启重试。**已有 static 始终优先，绝不被旧源覆盖**（包括空表）。
- `STATIC_DB_PATH`、`DYNAMIC_DB_PATH` 可指定路径。兼容 `DB_PATH` 作为 dynamic 别名，`DYNAMIC_DB_PATH` 优先。指定任一自定义 dynamic 路径时，static 默认是 `<dynamic路径>.static.db`，且不自动导入项目旧 `map.db`，避免测试或演示污染真实地图库；需要共用地图时显式指定 `STATIC_DB_PATH`。两个库和旧源路径不能相同。
- 部署迁移应先停旧服务并备份，由单一新服务实例完成首次启动；不要让旧、新版本同时继续写各自数据库。此迁移不尝试合并已有 dynamic 与后来变化的旧源。异常退出可能遗留 `*.migrating*` 临时文件，可在确认无迁移进程后删除。正常退出会关闭两个 SQLite 连接。
- 本阶段仅拆存储，不改业务模块协议。地点社区话题通过注入 staticDb 读取地图。地图修正脚本默认改为 static.db；`apply-place-curation.mjs` 在拆库后只改地图，不会跨库同步 dynamic 中菜单位置，菜单修正需另行受控执行。

活动自动更新的官网数据源默认开启；通知邮件数据源需要额外设置 `EVENT_IMAP_URL=imaps://账号:授权码@服务器:993`。可选环境变量包括 `EVENT_IMAP_MAILBOX`、`EVENT_MAIL_SENDERS`、`EVENT_IMAP_SINCE_DAYS`、`EVENT_IMAP_INTERVAL_MIN`、`EVENT_OFFICIAL_INTERVAL_MIN` 和 `EVENT_SYNC_ON_START`，详见 `.env.example`。163 等邮箱使用授权码，不要填写网页登录密码。没有配置 IMAP 时，后台会显示该数据源未配置，不影响官网活动同步。

测试：`npm run build && npm test`。覆盖导航、楼群、地下无状态路网、活动解析与数据管道，以及管理 API 的鉴权、点位与楼宇增删改、几何校验、重启持久化、空库不重复初始化、前后台独立入口。API 测试使用临时数据库和随机本地端口，不修改工作数据库。

## 数据

全部来自赛前数据包 `上科大智慧地图_赛前准备包/datapack`（坐标 BD-09，对齐手绘底图，见其中 `reference/projection.md`）。
`npm run data` 重新生成 `public/data/` 和 `public/tiles/`（默认读 `../上科大智慧地图_赛前准备包/datapack`，也可以把路径作为参数传进去）：

1. 保留两段风雨长廊（后台人工描的轮廓），不增加遮雨标记；删除重复的近似点位、介绍挪到轮廓上
2. 只保留校园边界内的点位（校外公交站、地铁口、周边商场不要）
3. 复制瓦片
4. 应用 `data/building-outline-refinements.json` 中逐栋核对的轮廓修正，重新生成数据时保留修正结果；如果源数据里的同一轮廓已被另外修改，则停止并报告冲突
5. 应用 `data/construction-outline-refinements.json` 的两处在建用地边界，以及 `data/place-curation.json` 的地点归属和去重记录

构建时 `scripts/road-network.mjs` 会把栅格中历史上区分的道路来源统一为可走单元；前台按可走 / 不可走、风雨长廊覆盖和少量建筑边缘挡雨计算路线。`public/data/underground.json` 及 `public/data/underground/` 保存地下图纸与路网数据，地下道路不会自动加入晴天地面导航。

2026-10-16 核对原有 61 个区域对象，并将 4 个有独立楼体的点位升级为建筑，共 65 个。边界沿手绘图可见的屋顶和立面，排除地面阴影；11–13 号楼按前后遮挡拆开，操场跑道和看台用独立轮廓表示。医务室对应服务中心最北侧楼体，校史馆对应三栋红顶小楼的中间一栋。耐思咖啡对应学生公寓1号楼最左侧临路灰顶小楼，学生活动中心对应右侧连接体，上海银行对应道路另一侧白顶楼；肯德基位于3号楼西侧小楼。两处在建区域按可见用地边界勾选，保留在建提示。

已有数据库不会随静态数据自动覆盖。先运行 `node scripts/apply-building-outlines.mjs`，再运行 `node scripts/apply-place-curation.mjs` 预览，分别加 `--write` 写入（可在命令后指定数据库路径）。第一步更新轮廓和标签中心，第二步合并 12 个重复点位、将 4 个点位升级为建筑，并同步菜单目录的位置和搜索别名。写入前完整备份所改表到数据库旁的 `backups/`，整批使用事务，保留现有菜单、价格及其他资料；遇到后续人工修改则报告冲突。重复执行不会重复写入，也不会恢复已删除记录。修正清单保留原始及早期已校对版本，支持从原始数据或已整理过的版本继续迁移。

`poly` 表示主体轮廓，`parts` 表示不相连的附属轮廓（例如看台、第二块在建用地），不会把中间的道路或草地填满。前台选中、透明度遮罩、范围定位及后台逐部分编辑均使用完整轮廓。

楼宇和点位初始化之后以 `server/static.db` 为准，重新跑 `npm run data` 不会覆盖已有修改。删除全部记录后重启也不会恢复已删除内容。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/places` | 分类、全部楼宇与全部点位（前后台共用） |
| GET | `/api/events`、`/api/canteens` | 活动和食堂目录；服务器同步后的数据库快照 |
| POST | `/api/account/code`、`/api/account/verify` | 邮箱验证码登录；默认预填上科大邮箱，也支持其他有效邮箱 |
| GET | `/api/account/me` | 查看当前校园账号（昵称、打码邮箱、角色、是否已起昵称） |
| PATCH | `/api/account/profile` | 修改账号昵称：2–16 个字，账号之间不能重名，普通账号不能含“管理员”“官方”等字样 |
| POST | `/api/account/logout` | 登出并换发匿名会话 |
| GET / PUT | `/api/me/data`、`/api/me/data/:key` | 登录后的 today / map / prefs 同步，单项最多 200 KB |

| GET / POST | `/api/organizer/events` | 主办方活动列表和新建（校园账号 `organizer` / `admin`） |
| PUT / DELETE | `/api/organizer/events/:id` | 主办方修改或删除自己的活动，管理员可管理全部 |
| GET | `/api/events/pipeline` | 管理后台读取官网 / IMAP 数据源状态、运行记录和目录统计；需要管理口令 |
| POST | `/api/events/pipeline/run` | 管理员立即运行全部或指定活动数据源 |
| GET | `/api/events/review?status=pending` | 读取待审核、已通过或已拒绝的活动条目；需要管理口令 |
| POST | `/api/events/review/:id/approve`、`/reject` | 管理员编辑后通过或拒绝活动条目 |
| GET / POST | `/api/events/:id/checkin-code`、`/api/events/:id/checkins`、`/api/events/:id/checkin` | 主办方获取签到码、查看签到人数、当前账号签到 |
| GET | `/api/events/sync/status` | 管理后台读取官网活动最近同步时间和统计；需要管理口令 |
| POST | `/api/events/sync` | 管理员立即同步官网活动；失败保留旧目录 |
| GET | `/api/crowd` | 最近 30 分钟各食堂窗口的排队反馈聚合（按时间衰减） |
| POST | `/api/crowd/:outlet` | 匿名用户反馈窗口排队等级和预计等待时间；同一窗口 10 分钟内限报一次 |
| GET | `/api/pois`、`/api/buildings` | 点位或楼宇列表 |
| POST | `/api/auth` | 校验口令 |
| GET | `/api/admin/events` | 后台活动目录（含隐藏、置顶、人工修改）和每场活动的讨论数 |
| PUT | `/api/admin/events/:id` | 修改活动字段、隐藏或取消；同步来的活动改动记入 `manualOverrides` |
| PUT | `/api/admin/event-pins` | 按 `ids` 顺序设置置顶，未列出的取消置顶 |
| GET / DELETE | `/api/admin/community`、`/api/admin/community/posts/:id`、`/api/admin/community/comments/:id` | 讨论管理：按话题类型、话题和关键词列出笔记，删除笔记或评论 |

| GET | `/api/admin/system` | 系统运行状态、数据规模、关键配置和备份文件 |
| POST | `/api/pois` | 新增点位（`name.zh`、`cat`、`pos` 必填） |
| POST | `/api/buildings` | 新增楼宇（`name.zh`、`cat`、`center`、至少 3 个轮廓顶点必填） |
| PUT | `/api/pois/:id`、`/api/buildings/:id` | 部分字段更新，合并原记录 |
| DELETE | `/api/pois/:id`、`/api/buildings/:id` | 删除记录 |

以上地图管理、活动数据管道、待审核和签到码后台接口都要 `Authorization: Bearer <管理口令>`；主办方活动发布接口使用校园账号角色鉴权；社区和排队反馈写接口使用同一份 HttpOnly Cookie 会话，并要求同源的 `X-Community-Request: 1` 请求头。排队图片、身份和反馈内容都不写入前端本地存储。

## 科大 · 同频：活动与档口交流

每场活动详情、每个档口菜单标题、菜品详情，以及每个楼宇和点位的详情（理发店、图书馆自习区、办事窗口等，校门和风雨长廊除外）均可进入独立交流区。地点交流区在第一次访问时按需创建，确认楼宇或点位存在后才建，名称和资料随后台修改同步；地点删除后已有讨论仍可查看。支持图文笔记（最多 4 张图片）、分享／提问／测评／攻略／约伴标签、评论与回复、点赞、收藏、搜索，以及最新／热门／我的收藏筛选。桌面为宽屏弹窗，手机为全屏双列卡片。

首次访问会生成一个匿名会话，只用于浏览、点赞、收藏和排队反馈，不对外显示名字。会话由 HttpOnly、SameSite Cookie 保存一年；浏览和查看总结无需登录，但发布笔记、评论、图片和签到必须先用邮箱验证码登录。公开署名用的昵称绑定在账号上：新账号首次登录时起昵称，之后在「我的」里修改，换设备登录还是同一个昵称；没起昵称的账号不能发笔记和评论。登录会把当前匿名会话里的内容迁移到账号，换设备后个人数据通过 `/api/me/data` 同步；登出后会换发新的匿名会话。所有帖子、评论、点赞、收藏、身份、图片 BLOB 和 AI 总结均保存在 `server/dynamic.db`，不是 localStorage。删除笔记会级联删除图片、评论、互动和对应旧总结。

### 校园账号、活动和课表识别

复制 `.env.example` 到 `.env` 后配置 `SMTP_URL` 与 `MAIL_FROM` 即可发送登录验证码；`DEMO_MODE=true` 时验证码打印在后端日志，`demo.test` 可用于演示登录和导入课表。主办方在 `/admin/` 的「活动」页登录后可以创建活动、选择地点并生成带 `?event=` 二维码的海报，账号需要 `organizer` 或 `admin` 角色。课表截图通过 `/api/schedule/parse` 发给 DeepSeek Flash，默认模型为 `deepseek-flash`，密钥只从服务端的 `SCHEDULE_VISION_API_KEY`（或兼容的 `DEEPSEEK_API_KEY`）读取，地址可用 `SCHEDULE_VISION_BASE_URL` 覆盖。

### DeepSeek 配置

复制 `.env.example` 到项目根目录 `.env`，填写 `DEEPSEEK_API_KEY`，再启动／重启 `npm run server`。已有环境变量优先于文件。`.env` 已忽略，**不要使用 `VITE_` 前缀**，不要提交密钥。模型可通过 `DEEPSEEK_MODEL` 配置，默认 `deepseek-flash`；实现遵循 [DeepSeek 官方 Chat API](https://api-docs.deepseek.com/) 和 [JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/)。

AI 请求由服务器发往 `https://api.deepseek.com/chat/completions`，前端只访问本站接口。点击生成才调用；发送活动／档口已收录资料、最新最多 40 篇笔记（每篇正文最多 600 字）、最新最多 80 条评论（每条最多 180 字），不发送昵称、身份凭据或图片。返回概览、重点和待确认问题；页面显示采样数量、生成时间、AI 提示。无讨论时明确说明暂无同学反馈，不生成虚构评价。资料、帖子或评论变化后标记旧总结待更新，删除内容即清除旧总结。同一资料版本复用数据库缓存，并合并同一交流区并发请求。

内置 45 秒请求超时、失败重试入口、缺少密钥／余额不足／无效密钥／服务繁忙提示。单 IP 每分钟最多 6 次新总结，全站每小时最多 60 次（计数持久化），同时最多 3 个生成任务。帖子、评论、上传另有限流。图片在浏览器缩至最长边 1400px、转成 JPEG（移除原图 EXIF 信息），后端限制每张 2MB，仅接受 JPEG／PNG／WebP。未发布图片 24 小时后在下一次上传时清理。

部署时持久化并备份 `server/static.db` 和 `server/dynamic.db`（运行中的 SQLite 请使用 backup API 或连同 WAL 一致备份）。HTTPS 反向代理部署设置 `COOKIE_SECURE=true`，转发原始 Host，让社区同源检查正确工作。开发代理已配置保留 Host。接口不开放跨站 CORS，写请求需要 `X-Community-Request: 1` 与同源 Origin（若浏览器提供）。

### 社区接口

| 方法 | 路径（前缀 `/api/community`） | 用途 |
|---|---|---|
| POST | `/session` | 创建／恢复匿名会话 |
| GET / POST | `/topics/:type/:id/posts` | 分页读取／发布笔记；`type=event/stall/place`，GET 支持 `sort=latest/hot/saved`、`q`、`offset` |
| GET / DELETE | `/posts/:id` | 读取／删除自己的笔记 |
| PUT | `/posts/:id/reactions/:kind` | `kind=like/save`，正文 `{active: boolean}`，幂等写入 |
| GET / POST | `/posts/:id/comments` | 分页读取／发布评论，回复使用 `parentId` |
| DELETE | `/comments/:id` | 删除自己的评论 |
| POST | `/images` | 上传图片 data URL |
| GET / DELETE | `/images/:id` | 查看图片／移除自己的未发布图片 |
| GET / POST | `/topics/:type/:id/summary` | 读取缓存状态／生成或复用总结 |

话题类型为 `event` 或 `stall`；活动使用原 ID，档口 ID 为 `canteenId:outletId:stallId`（作为 URL 路径段时编码）。仅能访问数据库目录中真实存在的话题。

`server/community.test.mjs` 使用临时 SQLite 与模拟 DeepSeek，覆盖全部话题建立、话题隔离、权限、图片、回复归属、幂等互动、重启持久化、级联删除、总结缓存失效、并发合并及上游异常。运行 `npm test` 不消耗 DeepSeek 额度、不修改工作数据库。
