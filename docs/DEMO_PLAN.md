## ⑪ 校园账号登录

**场景**：小科第一次打开，点首页右上角「登录」，输入校内邮箱、收到验证码，登录后昵称、帖子都还在。访客不登录也能看地图、导航、看活动。

**哪些地方需要登录**：同步个人数据（⑫）、发布笔记／评论／图片、签到（⑮）、发布活动（⑯）。地图、导航、活动和菜单浏览保持匿名可用。

**后端**（`server/account.mjs`，在 `index.mjs` 里挂载）：
- 复用交流区现有的 `community_users` 和 `campus_session` Cookie（HttpOnly，路径 `/api`）。登录就是给当前的匿名用户绑定邮箱，之前发的帖子和排队反馈不丢。
- 新表：
  - `accounts(user_id PK → community_users, email UNIQUE, role TEXT DEFAULT 'student', created_at)`，`role` 取 `student | organizer | admin`
  - `login_codes(email, code_hash, expires_at, tries, created_at)`
- 接口：
  - `POST /api/account/code { email }`：只接受 `@shanghaitech.edu.cn` 及其子域（`DEMO_MODE` 下另外接受 `@demo.test`）。生成 6 位验证码，10 分钟有效，只存哈希；同一邮箱 1 分钟一次，同一 IP 每小时 10 次
  - `POST /api/account/verify { email, code }`：最多试 5 次。邮箱已经有账号时，把会话切到那个账号；当前匿名用户没绑定过账号、并且发过内容的，内容合并过去
  - `GET /api/account/me` → `{ id, name, email（打码）, role }`；未登录返回 `null`
  - `POST /api/account/logout`：作废当前会话，换发一个新的匿名会话
- 发信：环境变量 `SMTP_URL`、`MAIL_FROM`，需要加一个 `nodemailer` 依赖。`DEMO_MODE` 下不发信，验证码打印在服务器控制台。
- 写接口沿用交流区的同源检查和 `X-Community-Request: 1` 请求头。
- 和 PLAN.md P2「账号权限」的关系：主办方和管理员角色先放在 `accounts.role` 里，P2 再加食堂老师角色、按食堂或活动划分的权限范围，以及后台登录。现在的管理口令先保留。

**前端**：`src/lib/account.ts`（状态、登录、登出）、`AccountDialog.vue`（邮箱 → 验证码两步）、`HomePanel.vue` 顶部头像或「登录」入口。交流区里，已认证用户的昵称旁边显示「已认证」。

**测试**：`server/account.test.mjs` 覆盖邮箱域名校验、验证码过期、试错上限、限速、匿名用户绑定后帖子保留、切换到已有账号、登出后换成新会话；不发真实邮件（注入假的发信函数）。

**验收**：手机上用演示邮箱登录，刷新后还是登录状态；之前匿名发的帖子作者还是自己；登出后可以继续浏览和导航。

## ⑫ 个人数据跟着账号走

**场景**：小科在电脑上导入课表，手机上打开就能看到；换手机也不丢。

**现状**：「我的今天」只存在 `localStorage`（`stmap.today.v1`）。地图标签的显隐目前连本机都不保存。

**后端**：
- 表 `user_data(user_id, key, data, rev, updated_at, PRIMARY KEY(user_id, key))`，`key` 只允许 `today`、`map`、`prefs`
- `GET /api/me/data` 返回全部；`PUT /api/me/data/:key { data, rev }`，`rev` 对不上时返回 409 和服务端版本；单项不超过 200 KB
- 需要登录，否则返回 401

**前端**（`src/lib/userData.ts`，通用同步存储）：
- 未登录：照旧只存本机
- 登录后：先读服务端。本机有、账号里没有的项，弹出「把这台设备上的 N 项合并到账号」；以后改动防抖 1 秒上传，断网时先存本机，联网再传
- 合并规则：`PlanItem` 加 `updatedAt`；删除改成墓碑记录（`deleted: true`，30 天后清掉）；遇到 409 时按 id 逐项合并，取 `updatedAt` 新的那份
- 登出：清掉账号数据的本机缓存，回到这台设备自己的匿名数据

**改动**：`server/account.mjs`（或单独的 `server/userData.mjs`）、`src/lib/userData.ts`、`src/lib/today.ts`（存储换成 userData，`importItems` 不变）。

**测试**：前后端都测合并（新增、修改、删除、两端同时改）、409 重试、断网恢复、登出清缓存。

interface MapPrefs {

## ⑭ 菜品全校分布

**场景**：搜「麻辣香锅」，第一条是「全校 2 家食堂有：尚科食堂 2 楼、白玉兰食堂 1 楼」。点开后，地图上这两家食堂被圈出，带角标「¥2.28/50g · 人少 · 步行 5 分钟」（两家都是称重，价格一样，差别在排队），其他食堂淡化；列表按「现在能吃、离得近、排队短」排序，「导航到最近一家」。

**现状**：搜索结果最多列 8 道菜（`store.ts` 里 `searchMenu(q).items.slice(0, 8)`），地图上没有反应。数据里确实有麻辣香锅：尚科食堂 2 楼和白玉兰食堂 1 楼各有一道，另有「香锅冒菜」等相近菜名。

**做法**：
- `menu.ts` 加 `groupByCanteen(items)`（纯函数）：按食堂 → 窗口分组，给出价格区间、是否在供应、命中几道菜
- 搜索：菜品结果命中两家及以上食堂时，在最前面加一行汇总结果，点开进入 `DiningPanel` 的「全校分布」视图（`state.dishFocus = 查询词`）
- 地图：`MapView.vue` 加 `drawDishFocus()`，命中的食堂高亮并显示角标，角标里有价格区间、排队等级（`crowdAt`）、步行分钟数（从我的位置或今天的下一站算）；点角标打开对应的 `CanteenDetail`，筛到这个窗口
- 现有的价格查询（「15元以内的牛肉」）也走同一个视图

**测试**：`menu.test.ts` 加分组、价格区间、不供应的排在后面。

**验收**：「麻辣香锅」显示 2 家；「15元以内的牛肉」能分组；关掉面板后地图恢复原样。

## ⑮ 活动签到与「到场」标记

**场景**：小科到了学生公寓8号楼 1 楼科道书院研讨室，扫门口签到屏上的码，提示「已签到 · 科道探索 · 生涯讲座 · 第 28 位」。他在活动交流区发帖，名字旁边显示「到场」。

**防止远程签到**：签到码 = HMAC(服务端密钥, 活动 id + 当前 5 分钟时段)，主办方屏幕每分钟刷新一次。服务端接受当前和上一个时段，只在活动开始前 30 分钟到结束之间有效。

**后端**：
- 表 `event_checkins(event_id, user_id, at, PRIMARY KEY(event_id, user_id))`
- `GET /api/events/:id/checkin-code`：只有该活动的主办方或管理员能拿
- `POST /api/events/:id/checkin { code }`：需要登录，重复签到返回已签到
- `GET /api/events/:id/checkins` → `{ count, me }`
- 交流区 `postJson` 加 `attended`；密钥 `CHECKIN_SECRET`，没有设置时像管理口令一样自动生成到文件

**前端**：链接 `?checkin=<活动 id>&code=…`（`deepLink.ts`）。未登录时先弹登录框，登录完继续签到。主办方在活动详情里能打开「签到码」全屏页；交流区显示「到场」；「我的今天」里对应的活动标为已参加。

**测试**：过期签到码、提前或结束后签到、非主办方拿签到码、重复签到。

## ⑯ 主办方发布活动与海报

**场景**：信息学院的王老师（虚构）登录 `/admin/`，打开「活动」页，新建周三下午的学术报告：填时间，在地图上点学校报告厅，写中英文简介，保存。然后点「生成海报」，下载一张带二维码的竖版图片，再给门口立牌生成一个「从北门导航过去」的指引码。

**后端**：
- 主办方 = `accounts.role` 为 `organizer` 的账号。管理员在后台「账号」页按邮箱授予这个角色
- 表 `custom_events`：字段和 `CampusEvent` 一致，另加 `owner`、`title_en`、`desc_en`、`created_at`、`updated_at`。`GET /api/events` 返回时并进活动目录（`source: 'organizer'`）；新建时调用 `ensureEventTopics` 生成交流话题
- 写接口：`POST /api/organizer/events`、`PUT` / `DELETE /api/organizer/events/:id`，只能改自己的；管理员可以改全部
- 官网同步来的活动，主办方不能直接改；管理员在同一个页面改，写进现有的 `event_overrides`（顺便把 PLAN.md P2 的「活动修正」界面做掉）
- 鉴权：`requireRole('organizer' | 'admin')` 读 `campus_session` 会话，和现在的管理口令并存

**后台**（`src/admin/EventWorkspace.vue`）：
- 左边是我的活动列表（管理员能看到全部，另有一栏「未定位」）；右边是编辑表单
- 地点用现有的 `AdminMap` 点选楼，或者搜索，房间号用 `findRooms` 校验。顶部显示「学校报告厅」这样的地点预览
- 「生成海报」：用 canvas 画 1080×1920 PNG，内容有标题、时间、地点和房间、中英文各一行简介、二维码（`?event=<id>`），可以选几套配色
- 「门口指引码」：`?to=<地点>&room=<房间>&from=<校门 id>`

**前端小改动**：`deepLink.ts` 支持 `from=`（导航起点；手机定位成功后自动改成我的位置）。

**测试**：主办方只能改自己的活动；自定义活动出现在 `/api/events`、活动地图钉和交流区；删除自定义活动后话题保留为只读；`from` 参数非法时忽略。

**验收**：后台新建活动后，前台刷新就能在活动雷达和地图钉上看到；海报二维码用手机扫开就是这个活动。

## ⑰ 访客英文落地页（P1 双语的子集）

**场景**：学者扫海报，打开的是英文活动卡片：标题、时间、地点、简介，下面一个大按钮「Navigate」。允许定位就从当前位置出发；不允许的话，选「I'm at: North Gate / South Gate / Parking」。开车来的先导到车库出入口，下车后继续步行导航。全程不出现登录框。

**做法**：
- 按 PLAN.md P1 的方案先建 `src/lib/i18n.ts` 和中英文字典，这次只翻译访客会经过的页面：活动详情、`EventCard`、`RouteCard`、`PlaceCard` 头部、`ShareDialog`、搜索框提示、定位提示。其他页面以后在 P1 里补
- `?lang=en` 打开英文，页面上也能切换；扫活动码时，手机系统语言不是中文的自动用英文
- 活动标题和简介优先用 ⑯ 填的 `title_en` / `desc_en`，没有就显示中文原文
- 起点选择：`from=` 参数，或者在导航卡片里列出校门和车库出入口
- 车库：起点选「Parking」时，路线终点之前先经过最近的车库人行出口。楼梯和电梯的点位要先现场采集（PLAN.md ⑨ 还欠着）

**测试**：中英文字典键一致（单测）；`?lang=en&event=…` 打开后关键文字是英文；没有英文字段时退回中文。

**验收**：在一部系统语言为英文的手机上扫海报，从北门导航到报告厅，全程是英文，不需要登录。
