## ① 教室号全局搜索

**场景**：新生在搜索框输入「1A-108」「SEM501」「图书馆302」「5-105」，第一条结果就是「1A-108 · 信息学院1号楼 · 1 楼」。点开后选中这栋楼，房间目录直接定位到这个房间，可以一键导航到入口。

**现状**：551 间房只存在 5 栋楼的 `rooms` 里（信息学院 1、2 号楼，人字楼，创管，生医工），只能在楼详情里查。图书馆、教学中心、物质学院没有房间表，但活动和课表大量在这些地方。

**解析规则**（`src/lib/roomSearch.ts`，按可信度从高到低）：

1. **房间表精确匹配**：编号或名称（忽略空格、横线、大小写）。可信度 `exact`。
2. **楼名或别名加号码**：「图书馆302」「教学中心 101」「SEM501」「创艺南楼S301」。先用楼名、简称、别名匹配前缀，剩下的部分当房间号。楼层取号码首位，`B` 开头为地下。可信度 `rule`。
3. **编号规则**：
   - `1A-108`（数字 + A–E + 三位数）→ 信息学院 1 号楼
   - `5-105`（数字-三位数）且不在房间表里 → 物质学院 N 号楼（信息学院 2 号楼的 `2-xxx` 已在表里，会先命中第 1 条）
   - `SEM501` → 创业与管理学院
4. **活动历史投票**：760 条活动带房间号和楼。统计 `(房间号 → 楼)` 出现次数，用于 `S301`、`B808` 这类只看编号判断不了楼的情况。可信度 `history`，结果里写「根据往期活动地点推测」。

**改动**：
- `src/lib/roomSearch.ts`：`findRooms(q): RoomHit[]`，返回 `{ building, code, floor, label?, confidence }`。
- `src/lib/store.ts`：`search()` 在查询里含数字时把房间结果放在最前；`SearchTarget` 增加 `{ kind: 'room', building, code }`；`chooseSearch()` 选中楼并记下 `state.room`；选导航端点时直接用这栋楼。
- `PlaceCard.vue` / `RoomDirectory.vue`：接收要定位的房间，自动筛选并高亮；推测出来的结果标「按房间号推测」。
- 地图：选中楼的标签显示「信息1 · 1A-108」。

**测试**：`roomSearch.test.ts` 覆盖上面每条规则和下面的验收例子，以及歧义编号不会给出错误的楼。

**验收**：`1A-108`、`1d108`、`SEM501`、`图书馆302`、`5-105`、`2-101`、`S301` 各自定位到正确的楼和楼层；纯楼名搜索的结果和现在一样。

## ② 今天时间线（「我的今天」）

**场景**：把课、收藏的活动、吃饭和待办排成一条时间线。地图上按顺序编号连成当天的行动轨迹，每两站之间显示步行分钟数。

**存储**：只存在手机上（`localStorage`，键 `stmap.today.v1`），读写都包 try/catch，浏览器禁用存储时退回内存并提示「当前浏览器不会保存」。

```ts
interface PlanItem {
  id: string
  kind: 'class' | 'event' | 'meal' | 'todo'
  title: string
  place?: string          // 楼或点位 id
  room?: string           // 教室号，用 ① 解析
  start: string           // 'HH:MM'
  end?: string            // 'HH:MM'
  date?: string           // 'YYYY-MM-DD'，一次性的安排
  weekdays?: number[]     // 每周重复（课程），1 = 周一
  eventId?: string        // 来自活动雷达
  note?: string
  source: 'manual' | 'event' | 'ai' | 'planner'
}
```

**界面**：
- 新面板 `today`：顶部的面板切换增加「我的今天」，首页增加入口卡片。
- 日期切换（今天 / 明天 / 选日期）；时间线按开始时间排序。过去的项淡化，正在进行的高亮，有一条「现在」的线。
- 两站之间显示「步行 N 分钟」（用 `findRoute` 算，结果按地点对缓存）；时间不够走过去时标红：「下课 11:50，到 SEM501 要 9 分钟，会迟到 4 分钟」。
- 下一项卡片：「下一项 14:00 SEM501，步行 6 分钟，建议 13:50 出发」，带「到这去」。
- 添加 / 编辑表单：类型、标题、地点（复用搜索，支持 ① 的教室号）、时间、每周重复。
- 活动详情增加「加入我的今天」；时间冲突时提示。
- 地图：在「我的今天」面板里显示编号地图钉和各段步行路线，按状态着色（已过 / 当前 / 后续），自动缩放到全天范围。

**给 ③ 留的接口**：`importItems(items, source)` 先显示预览，用户确认后再写入；③ 只需要产出 `PlanItem[]`。

**改动**：`src/lib/today.ts`（存储、按日展开重复项、排序、冲突、步行段）；`TodayPanel.vue`、`TodayItemForm.vue`；`MapView.vue` 增加 `drawToday()`；`store.ts` 面板类型增加 `today`；`EventsPanel.vue`、`HomePanel.vue` 增加入口。

**测试**：`today.test.ts` 覆盖每周重复展开、跨日、冲突、迟到判断，以及存储读写抛错时的退化。

**待补数据**：学校的上课节次时间表（数据包「赛前还要采集」里列了）。在拿到之前，表单直接填时间，不按节次换算。

## ③ 课表截图 AI 解析（后端为主，交给你）

**流程**：前端选图 → 压缩（复用 `preparePhoto`）→ `POST /api/schedule/parse` → 服务器调用视觉模型 → 返回结构化课程 → 前端表格预览、可改 → 确认后用 ② 的 `importItems` 写到手机。

**接口**：

```
POST /api/schedule/parse
请求  { image: 'data:image/jpeg;base64,…' }   ≤ 4 MB
响应  { classes: [{ title, weekday, start, end, room, weeks?, teacher? }], warnings: string[] }
```

**要点**：
- 模型：现在用的 DeepSeek chat 模型不接受图片，需要一个视觉模型（Claude、Qwen-VL、GLM-4V 等任选），密钥只放服务器环境变量，例如 `SCHEDULE_VISION_API_KEY`、`SCHEDULE_VISION_MODEL`。
- 隐私：图片只在内存里处理，不落库、不写日志；响应里不回传图片。README 里写明。
- 提示词要求严格 JSON；把「节次 → 时间」表放进提示词（等节次表补齐）；`room` 交给前端 ① 解析成楼。
- 防滥用：大小限制、按会话或 IP 限速（例如每分钟 3 次）、30 秒超时、失败返回可读错误。
- 文件：`server/schedule.mjs`，在 `server/index.mjs` 挂载；`server/schedule.test.mjs` 用假的 fetch 测成功、超时、坏 JSON、超限。
- 前端部分（`ScheduleImport.vue`：选图、上传、预览表格、确认导入）等接口好了再接，可以我来写。

**验收**：拿 3 张不同的教务系统课表截图测试，课程名、星期、时间、教室基本正确；识别错的可以在预览里改；断网或接口失败有提示。

## ⑤ 智能推荐（「我的今天」里的建议）

**输入**：② 当天的安排、步行时间（`findRoute`）、窗口营业时间（`outletState` / `hours`）、排队情况（`crowdAt`）、当天活动（`eventsIn`）。

**吃饭建议**：午餐 11:00–13:30、晚餐 16:30–19:00 两个窗口里，找前后两站之间的空档（要够走过去、吃 20 分钟、再走到下一站）。对每个营业中的食堂计算：上一站走过去 + 预计排队 + 走到下一站。选总耗时最短的，生成一条建议：

> 11:50 下课 → 步行 4 分钟到一食堂（预计排队 3 分钟，估算）→ 12:40 前回到 SEM501

建议卡片可以「加入我的今天」（生成 `meal` 项）或「到这去」。

**活动建议**：当天的活动里，只推荐时间完全放得进空档的（开始前走得到，结束后来得及去下一站），最多 3 场，按「离得近、马上开始」排序。

**动态调整**：每 30 秒随时钟更新；错过了某一项、或者 ⑥ 发现人离计划地点很远时，提示「按现在的时间重新安排」，只重排还没开始的建议，不动用户手动加的项。

## ⑥ 实时定位蓝点

**数据已经有了**：`public/data/campus.json` 里的 `warp` 包含 175 个路口控制点的仿射参数和残差。公式在数据包 `reference/projection.md`：WGS-84 → `wgsToBd` → `realToMap(p, campus.warp)`。

**做法**：
- `navigator.geolocation.watchPosition`（高精度）拿到坐标 → 转换后显示蓝点、精度圈（半径 = accuracy 米）和朝向扇形。
- 朝向：优先用 `DeviceOrientationEvent`（iOS 要在点击时调用 `requestPermission()`，读 `webkitCompassHeading`）；拿不到时，走动中用 GPS 的 heading。
- 地图右侧加「定位」按钮，状态：关闭 → 定位中 → 跟随（地图跟着走）→ 自由（用户拖动地图后停止跟随，再点一次回到跟随）。
- 不在校园里时提示「你不在校园内」，不显示蓝点。
- 导航：起点可以选「我的位置」；导航中偏离路线超过约 25 米、连续两次定位，就自动重算；到达终点时提示。
- 演示用模拟定位（室内 GPS 不准）：开发环境和 `?mock=lng,lat` 可以指定位置；也可以沿当前路线模拟行走。
- 浏览器只在 HTTPS 下给定位权限。生产环境要 HTTPS；手机上调试可以给 Vite 加 `@vitejs/plugin-basic-ssl`。

**改动**：`src/lib/geoConvert.ts`（`wgsToBd`、`realToMap`）、`src/lib/locate.ts`（定位状态）、`MapView.vue` 画蓝点、`RouteCard.vue` 支持「我的位置」。`geoConvert.test.ts` 用控制点验证转换，另测偏离路线的距离计算。

3. **账号权限**：把单一管理口令换成 `admin_users(id, name, password_hash(scrypt), role, scopes)` 加 HttpOnly Cookie 会话。角色：管理员（全部）、食堂老师（只能改指定食堂）、书院 / 学院（只能改自己主办的活动）。保留现在的口令作为第一个管理员的初始密码，兼容现有部署。
4. **操作日志**：`audit_log(id, user_id, action, entity, entity_id, before, after, created_at)`，在每个写接口里统一记录；后台加日志页，按人、对象、时间筛选，支持查看改动前后的差异。
5. **API 文档**：整理现有接口成一页文档（或 OpenAPI），方便书院和社团接入。

建议顺序：账号权限 → 操作日志 → 活动修正 → 食堂与菜品。权限和日志是其余几项的基础。

## P3 活动自动更新（后端为主，交给你）

**来源**：学校官网活动日历接口（数据包里的 `reference/official_events` 就是从这里来的）。邮件活动涉及个人邮箱，先不做自动化，继续人工导入。

**做法**：
1. `scripts/fetch-events.mjs`：拉取官网日历最近 60 天和未来 60 天，转换成现有 `CampusEvent` 格式。
2. 地点归并：复用数据包 `02_活动地点别名表` 的 182 种地点写法规则，加上 ① 的房间号解析，得到 `place / room / floor`；归并不了的标 `place: null`，进 P2 的「待定位」列表。
3. 入库：按 `source + 原始 id` 去重写入 `discovery_catalog`（或 P2 拆出来的活动表），不覆盖 P2 的人工修正；被官网删除的活动标记为已取消而不是直接删除。
4. 定时：服务器内用 `setInterval` 每 2 小时跑一次（或系统 cron），失败只记日志、保留旧数据；后台显示「最近同步时间、新增 / 更新条数」，并提供「立即同步」按钮。
5. 社区话题：新活动自动建话题（现有启动逻辑改成同步后也执行）。
6. 测试：用保存下来的官网响应做固定输入，测转换、去重、地点归并、失败不清空。

**风险**：官网接口格式可能变化，转换失败时要报警（后台提示）而不是写入空数据；访问频率保持在很低的水平。
