# 地上地下雨天一体化导航设计

## 目标

把现有地面步行栅格和地下候选路网组合成一套步行导航逻辑：晴天只使用地面；雨天在地面、风雨长廊和地下之间按实际淋雨代价择优，并在每个进入地下、回到地面的连接点给出清晰提示。

## 已确认约束

- 地面路径需要比当前栅格回溯更平滑，避免短距离锯齿。
- 连续较长的露天路段应优先换到地下或风雨长廊；约十米以内的短露天段保留地面。
- 风雨长廊算地面遮挡，地下全部算不淋雨。
- 相邻宿舍楼之间、食堂左右两条建筑边缘通道视作少量建筑挡雨区；只给很小的雨天收益，学院建筑不纳入挡雨区，雨天仍主要优先地下车库和风雨长廊。
- 地面和地下路线使用不同颜色；进入地下和回到地面显示分界点和步骤。
- 正式地下图目前为空；备份数据包含 18 条道路和 16 个连接点，全部为 `candidate`。本阶段将备份数据恢复到正式图，保留候选状态，并允许未 `rejected` 数据参与雨天计算。

## 路由模型

保留现有地面栅格寻路作为地面子图，并让它输出可用于跨图比较的天气代价。地下子图复用地下道路的折点、方向和连接点吸附逻辑；步行一体化默认接受 `walk` 和现有 `car` 几何道路，以兼容当前备份数据，所有地下边均标记为遮挡。

新的一体化寻路器在雨天把起点、终点和每个有效地面↕地下连接点作为元图节点。元图边分为地面路线和地下路线：地面边使用地面雨天寻路结果，地下边使用地下图寻路结果；每次跨层增加固定换层代价，使十米左右的短露天段不会为了地下而绕路。对元图跑 Dijkstra，拼接得到带 `layer`、`covered` 和连接点元数据的路线段。晴天直接返回地面路线，不创建地下边。

雨天比较时，地面连续暴露段只对超过 10 米的部分施加明显惩罚；风雨长廊和地下段不计入暴露长度，宿舍/食堂建筑边缘只按轻微降低后的雨天代价计算。若地下图没有可达路线，自动退回现有地面雨天路线。

## 展示和状态

`RouteResult` 的路线段增加 `layer: 'surface' | 'underground'`，并增加 `transitions`、`undergroundMeters` 和用于比较的内部天气代价。地图按地面露天蓝色、地面遮挡青色、地下紫色绘制；进入地下和回到地面的连接点用橙色分界标记。导航卡片统一展示一条路线，显示地上/地下图例、地下米数和“进入地下 / 回到地面”的连接点步骤。

地下编辑入口保留在图层控制中，编辑器仍可维护道路和连接点；前台导航不再通过切换“地面 / 地下”来选择路线。

## 数据迁移

从 `data/underground-sketch-backup-20261017.json` 恢复道路和连接点到 `public/data/underground.json`，不改变 `candidate` 状态。正式图以后可由后台把道路和连接点改成 `confirmed` 或 `rejected`，导航逻辑无需再改。

## 错误处理

- 地面或地下端点无法吸附时，返回现有的无路线状态。
- 地下连接点未能接到地下道路时，不参与元图，不阻塞地面路线。
- 地下数据为空、全部 rejected 或地下路线不连通时，雨天仍返回地面雨天路线。
- 现有候选状态、单向道路和无效数据校验规则保持不变。

## 验证

增加纯函数单测覆盖：短露天段选择地面、长露天段选择地下、建筑边缘缓冲记为遮挡、跨层段顺序和连接点标记、地下不可达时回退地面、候选/拒绝状态筛选，以及地面路径平滑后的连续性。最后运行 `npm test` 和 `npm run build`；已存在的服务器环境依赖失败单独记录。
