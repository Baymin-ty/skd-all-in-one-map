# 地面与地下路网后台编辑设计规格

## 目标

在 admin 中提供一个“路网编辑”工作区，让管理员能维护地面可走栅格和地下道路网络。修改应能保存、校验并被前台导航读取，同时保留现有静态数据作为回退，避免编辑数据不可用时整张地图失效。

## 当前模型与约束

- 地面路由使用 `public/data/campus.json` 的 `grid` 栅格，路由器把字符 `0` 和 `2` 视为可走单元，并在八邻域上计算路径。
- 地下数据使用 `public/data/underground.json` 的 `UndergroundMap`：道路是带 `floor`、`mode`、`status`、`direction` 的折线，连接点是带楼层、类型和位置的节点。
- 现有 admin 使用 Bearer 管理员令牌；地点编辑写入服务端 SQLite 数据库。
- 本功能不改变现有地面路由算法，也不要求把静态 JSON 改成部署时可写文件。

## 方案

新增一个路网数据模块和 `/api/network` 接口。服务启动时在当前 SQLite 数据库中创建 `network_overrides` 表，按 `kind` 保存 `surface` 与 `underground` 两个 JSON 覆盖项及更新时间。

- `GET /api/network` 不要求登录，返回 `{ surface, underground, updatedAt }`。服务端先读取覆盖项，缺失的部分从 `campus.json` 与 `underground.json` 提供。
- `PUT /api/network/surface` 要求管理员令牌，接受完整的地面网格 `{ x0, y0, dx, dy, rows }`，验证尺寸和字符后以事务写入。
- `PUT /api/network/underground` 要求管理员令牌，接受完整的 `UndergroundMap`，复用现有地下数据校验器，验证道路和连接点的 ID、边界、状态、楼层和几何最小长度后写入。
- 接口返回保存后的规范化对象和 `updatedAt`；格式错误使用 400，未登录使用 401，存储失败使用 500。

前台 `src/lib/store.ts` 在加载 campus 和 underground 静态数据后请求 `/api/network`，成功时用响应中的对应字段覆盖静态值；请求失败或字段缺失时继续使用静态数据。这样开发环境、离线页面和接口暂时不可用时仍能导航。

## Admin 工作区

在 `AdminApp.vue` 的主导航加入“路网编辑”，挂载新的 `RoadNetworkWorkspace.vue`。工作区顶部有两个标签：地面路网、地下路网；两个标签共享地图容器、保存栏、错误提示和未保存状态。

### 地面路网

地图使用当前 campus map 的坐标转换和 Leaflet 图层，将网格单元渲染为可编辑覆盖层。管理员可以：

- 选择画笔或擦除模式，并拖动连续绘制；
- 看到可走、不可走和当前修改单元的明确颜色；
- 撤销、重做当前会话中的修改；
- 点击保存，把完整网格提交到 `/api/network/surface`；
- 保存失败时保留本地修改并显示服务端错误。

编辑只改变网格行中的路网字符，保留原始坐标参数和行列数。画笔不会允许越过网格边界，也不会产生未知字符。

### 地下路网

地图显示道路折线和连接点，侧栏显示当前楼层和实体列表。管理员可以：

- 新增地下道路，设置楼层、模式、方向、状态和备注，并用点击创建至少两个顶点；
- 拖动道路顶点、增加或移除顶点；
- 新增连接点，设置起止楼层、类型、状态、位置和关联地点；
- 编辑现有实体的字段；
- 将道路或连接点标记为 `rejected` 以实现删除语义，并可恢复为 `candidate` 或 `confirmed`；
- 保存完整地图到 `/api/network/underground`。

保存前在客户端做快速校验，服务端再次执行权威校验。道路和连接点使用稳定 ID；保存时不得出现重复 ID。所有实体都必须位于地图 bounds 内，道路至少有两个有效顶点。

## 权限与并发

读取路网是公开的，因为前台地图本身公开显示；写入只接受现有 admin Bearer 令牌。保存使用完整文档替换并记录单一更新时间，不做字段级合并。工作区加载时记录 `updatedAt`；保存前如果服务端时间已变化，返回 409 并要求管理员重新加载，防止覆盖另一个管理员的编辑。

## 错误处理与回退

- 静态文件或数据库中的数据损坏时，服务端记录错误并返回可用的静态回退；若静态数据也无法解析，接口返回 500，前台保留当前已加载地图。
- 前台保存失败不清空编辑状态；管理员修复错误或重新加载后才能丢弃修改。
- 地下被标记为 `rejected` 的实体不参与现有地下寻路，符合当前 `undergroundRoute` 的状态过滤逻辑。

## 测试与验收

- 服务端测试覆盖：公开读取、管理员鉴权、地面网格字符和尺寸校验、地下几何与边界校验、重复 ID、保存后重新读取、更新时间冲突和静态回退。
- 前端测试或类型检查覆盖：画笔修改单元、撤销/重做、地下道路顶点编辑、状态删除语义和保存错误反馈。
- 运行 `npx vitest run` 和 `npm run build`。
- 浏览器验收：以管理员进入“路网编辑”，修改并保存一个地面单元；编辑并保存一条地下道路；刷新页面确认修改仍在；截取工作区截图作为验收证据。

## 范围边界

本次不改动路径搜索算法、不自动从卫星或 CAD 数据生成路网、不新增普通用户编辑权限，也不直接覆盖版本库中的静态 JSON 文件。后续如需批量导入，可在此 API 之上增加导入工具。
