# 活动详情采集、去重与报名建议设计

## 目标

活动采集结果不再只有标题和时间字段，而是包含可供前台展示的完整详情。官网活动页和学校通知邮件都作为来源，系统在合并后只保留一条活动记录，并在详情页提供报名信息和 AI 报名建议。

## 现状与边界

项目已有 `CampusEvent`、官网活动同步、IMAP 邮件同步、活动审核队列和前台活动详情页。当前同步结果主要包含标题、时间、地点、主办方、分类和来源 URL；详情页只展示少量描述字段。此次改动集中在活动数据流和活动详情展示，不改变地图、日程、社区讨论或签到的接口语义。

## 数据模型

`CampusEvent` 增加以下可选字段：

- `description`：清洗后的中文详情正文；
- `registrationUrl`：报名或预约链接；
- `registrationDeadline`：报名截止时间（ISO 字符串）；
- `sourceUrls`：合并后的来源链接列表；
- `sourceLabel` 或来源元数据：用于展示官网、邮件等来源；
- `aiRecommendation`：结构化 AI 结果，包含 `decision`（建议报名/可考虑/不建议）、`reason`、`audience`、`action` 和生成时间。

字段均保持可选，以兼容既有静态快照和旧数据库记录。服务端数据库保存 JSON 活动对象时沿用现有迁移策略，不新增无法回滚的强制列。

## 采集与清洗

官网同步先请求活动列表，再对有详情 URL 的记录请求详情页。详情页 HTML 只保留正文文本、段落和列表结构；移除脚本、样式、导航、重复标题、跟踪参数和过长空白，正文设置长度上限。解析失败时保留列表字段并记录 warning，不让单条详情失败中断整次同步。

邮件同步保留邮件主题、纯文本正文和必要的 HTML 转文本结果。去除签名、免责声明和明显的邮件引用内容；正文超过上限时截断并记录截断状态。报名链接从正文和 HTML 链接中提取，优先使用报名、预约、注册等文字附近的链接。

## 去重与合并

合并按以下优先级匹配：

1. 同一来源的稳定 ID；
2. 规范化标题 + 开始日期 + 地点；
3. 规范化标题 + 开始日期。

匹配后保留已有稳定活动 ID，并合并来源列表。正文选择较长且非空的版本，报名链接选择明确标注报名的链接，官网和邮件的时间地点以结构化字段优先；人工修改字段继续由现有 `manualOverrides` 规则保护。无法可靠匹配的记录进入现有审核队列。

## AI 报名建议

服务端新增独立的活动摘要函数，输入标题、时间、地点、主办方和清洗后的详情，输出严格 JSON。使用环境变量中的 AI API 配置；未配置、超时或返回非法 JSON 时，不阻断同步，活动详情显示“暂未生成报名建议”，并在同步 warning 中记录原因。建议结果只作为辅助信息，不自动替用户报名。

## 前台详情页

沿用现有 `?event=` 和 `EventsPanel` 详情状态。详情页在已有时间、地点、主办方信息下新增：

- 可折叠或分段展示的活动详情正文；
- 报名按钮和报名截止时间（有链接才显示）；
- AI 报名建议卡片，展示结论、理由、适合人群和下一步动作；
- 合并来源和最后采集时间。

没有详情或 AI 结果时显示明确的空状态，不影响原有导航、加入我的今天、分享和社区讨论。

## 后台与审核

后台活动编辑表单和待审核表单增加详情、报名链接、报名截止时间字段。自动同步写入的新字段可以被管理员修改，修改后遵循现有人工覆盖规则。审核通过时使用与现有字段相同的长度和格式校验。

## 测试与验收

增加服务端测试覆盖：官网详情解析、邮件正文清洗、报名链接提取、跨来源去重合并、AI JSON 解析失败降级；增加前端测试或类型检查覆盖详情字段兼容。运行现有 `npm test` 和 `npm run build`。
