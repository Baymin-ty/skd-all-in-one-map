# 避雨路网系统设计

## 1. 设计目标

系统提供一个独立于普通地面路网的“避雨路网”版本。用户在步行导航中打开“我要避雨！”后，导航不再使用普通地面栅格，而是使用管理员维护的避雨栅格。

避雨路网的核心语义是：

- 普通路网：正常情况下可通行的地面路网；
- 避雨路网：雨天希望保留的可通行路径；
- 管理员可以删除不适合雨天通行的格子，也可以重新恢复某些格子；
- 两个版本使用相同的坐标系、栅格尺寸和寻路算法。

本系统不再使用遮雨范围、雨天权重或道路等级。避雨模式通过**删除不可用路径**实现，而不是给露天路径增加代价。

## 2. 总体架构

```text
public/data/campus.json
        │
        ├── 普通路网：campus.grid
        │
        └── static.db / surface_networks / rain
                │
                └── 避雨路网：rain.grid

前台选择普通/避雨版本
        │
        ├── initRouting(grid)
        ├── 重新建立内存中的可走栅格
        ├── Dijkstra 重新计算路线
        └── MapView 重新绘制地面路网

管理后台
        │
        ├── 从普通路网或已保存的 rain 路网加载栅格
        ├── Canvas 画笔/擦除
        └── PUT /api/surface-networks/rain
```

系统仍然使用当前地面导航的栅格模型，不引入另一套道路节点和边模型。地下路网 `nodes + edges` 不受本系统影响。

## 3. 栅格数据模型

### 3.1 基础结构

普通路网和避雨路网都使用 `Campus.grid`：

```ts
interface SurfaceGrid {
  x0: number
  y0: number
  dx: number
  dy: number
  rows: string[]
}
```

字段含义：

| 字段 | 含义 |
|---|---|
| `x0` | 栅格左侧起始经度 |
| `y0` | 栅格顶部起始纬度 |
| `dx` | 单格经度间隔 |
| `dy` | 单格纬度间隔 |
| `rows` | 栅格行字符串，每个字符代表一个格子 |

当前校园栅格约为 `250 × 172`，每格约 5.4 米。

### 3.2 格子值

普通路网沿用 `campus.json` 的既有数据：

- `0`：可走；
- `2`：可走，历史上代表另一种道路来源；
- 其他字符：不可走。

避雨路网保存时只允许：

- `0`：避雨模式下可走；
- `1`：避雨模式下不可走。

后台的“画笔”将格子设为 `0`，“擦除”将格子设为 `1`。避雨路网不保存 `2`，避免继续携带已经不参与导航语义的道路来源信息。

### 3.3 版本关系

```text
普通版本：campus.grid
避雨版本：surface_networks.id = 'rain'
```

避雨版本不是对普通文件的覆盖，而是独立保存的完整栅格副本。没有保存过避雨版本时，后台会以普通路网作为编辑初始值；前台此时显示“暂无避雨版本”，不会错误地把普通路网当作已配置的避雨路网。

## 4. 数据库存储

避雨路网存储在 `server/static.db` 的 `surface_networks` 表：

```sql
CREATE TABLE surface_networks (
  id TEXT PRIMARY KEY,
  data TEXT NOT NULL,
  updated_at INTEGER NOT NULL
);
```

当前使用的固定记录：

```text
id = 'rain'
```

`data` 是完整的 `SurfaceGrid` JSON，例如：

```json
{
  "x0": 121.6001,
  "y0": 31.1842,
  "dx": 0.00005,
  "dy": 0.00005,
  "rows": [
    "111111000011",
    "111100000011",
    "111111111111"
  ]
}
```

静态地图、地下地图和动态业务仍分别存储，不把避雨路网写入 `dynamic.db`、旧的 `map.db` 或地下地图表。

## 5. 服务端 API

实现文件：

```text
server/surfaceNetworks.mjs
```

### 5.1 获取所有版本

```http
GET /api/surface-networks
```

返回普通版本和已保存的避雨版本：

```json
{
  "default": { "x0": 0, "y0": 0, "dx": 1, "dy": 1, "rows": [] },
  "rain": null,
  "updatedAt": 0
}
```

如果已经保存避雨版本，`rain` 为对应栅格对象。

### 5.2 获取单个版本

```http
GET /api/surface-networks/default
GET /api/surface-networks/rain
```

普通版本由服务端当前加载的 `campus.grid` 直接提供。避雨版本不存在时返回：

```json
{
  "grid": null,
  "updatedAt": 0,
  "available": false
}
```

### 5.3 保存避雨版本

```http
PUT /api/surface-networks/rain
Authorization: Bearer <admin-token>
Content-Type: application/json
```

请求体：

```json
{
  "grid": {
    "x0": 121.6001,
    "y0": 31.1842,
    "dx": 0.00005,
    "dy": 0.00005,
    "rows": ["...", "..."]
  }
}
```

服务端会校验：

1. 坐标参数是有限数字；
2. `x0/y0/dx/dy` 必须和普通路网一致；
3. 行数必须一致；
4. 每行列数必须一致；
5. 避雨路网格子只能使用 `0` 或 `1`；
6. 请求必须经过管理员鉴权。

写入前会对运行中的 SQLite 数据库执行 online backup，并检查备份的 `PRAGMA quick_check`；之后在事务中更新记录。

## 6. 前台导航流程

### 6.1 初始化

`src/lib/store.ts` 启动时加载：

1. `/data/campus.json`，得到普通路网；
2. `/api/surface-networks/rain`，尝试加载避雨版本；
3. 普通路网加载后调用 `initRouting()`；
4. 避雨版本存在且校验通过时，启用“我要避雨！”开关。

后端不可用或避雨版本不存在时，普通导航仍可使用。

### 6.2 切换模式

切换“我要避雨！”时：

1. 保留当前起点和终点；
2. 选择普通或避雨栅格；
3. 重新调用 `initRouting()`；
4. 重建 `route.ts` 内部的可走格数组；
5. 重新计算当前路线；
6. 递增路网版本号，触发 MapView 重绘蓝色路网。

`route.ts` 使用模块级路由状态，因此不能只修改 Vue 中的 `campus.grid`。每次版本切换都必须重新初始化路由器。

### 6.3 地面寻路

地面路网仍使用 8 邻接 Dijkstra：

```text
上、下、左、右、左上、右上、左下、右下
```

每个可走格是一个节点，相邻可走格之间自动形成连接。直行和斜行按实际地理距离计算。

避雨模式不会修改：

- Dijkstra 算法；
- 格子之间的距离；
- 步行速度；
- 起点和终点吸附规则；
- 路径平滑逻辑。

它只修改参与寻路的可走格集合。

### 6.4 地下路线

地下路线继续使用地下地图中的 `nodes + edges`。切换避雨模式后，地面到地下连接点的接驳部分会使用当前选中的地面栅格；地下部分仍使用独立地下图。

当前集成导航仍沿用既有的“地面 → 地下 → 地面”候选逻辑，避雨模式没有增加额外地下代价。

## 7. 地面路网显示

“显示统一地面路网”显示的是当前选中版本的全部可走栅格连接：

- 普通模式显示普通栅格；
- 避雨模式显示避雨栅格；
- 所有连接统一使用蓝色；
- 不再区分蓝色/青色遮雨属性。

`walkablePaths()` 与 `findRoute()` 使用同一个内存栅格：

```text
图层显示：遍历当前版本的全部 8 邻接连接
导航计算：在当前版本中寻找起点到终点的最短路线
```

因此打开路网显示后，看到的就是当前导航算法所使用的地面路网，而不是另一份仅用于展示的数据。

## 8. 后台编辑器

相关文件：

```text
src/admin/RainNetworkWorkspace.vue
src/admin/rainStore.ts
src/lib/network.ts
```

### 8.1 编辑流程

1. 登录管理后台；
2. 进入“避雨路网”；
3. 加载已保存的避雨版本；
4. 如果尚未保存，则从普通路网复制一份作为草稿；
5. 使用画布编辑格子；
6. 点击“保存避雨版本”。

编辑器不会直接修改普通路网、地下路网或地点数据。

### 8.2 编辑工具

- **画笔 · 可走**：把格子设置为 `0`；只能涂抹在普通路网原本可走的格子上，不能凭空创造新的雨天路径；
- **擦除 · 不可走**：把格子设置为 `1`；可以涂抹在任意格子上；
- **画笔大小**：可选择 `1×1`、`3×3`、`5×5`、`7×7`、`9×9` 方形画笔，以落点为中心覆盖对应区域，便于快速标记大片露天或连廊区域；
- **显示背景图**：默认开启，在栅格下方渲染校园地图底图（百度瓦片），禁用交互、仅作参照；关闭后回到纯白背景；
- **撤销**：恢复上一次栅格快照；
- **重做**：恢复已撤销的栅格快照；
- **放弃修改**：回到最近一次加载或保存的版本；
- **保存避雨版本**：通过管理员 API 写入静态数据库。

编辑器使用 Canvas 绘制栅格，避免为数万个格子创建独立 Leaflet 图层。鼠标和触控拖动都可以连续涂格。大画笔会在拖动路径上连续覆盖，边界格子会被自动裁剪。开启背景图时，可走格和不可走格使用半透明色，以免遮挡地图细节。

### 8.3 未保存保护

存在未保存修改时：

- 后台切换页面会提示确认；
- 浏览器关闭或刷新会触发离开提示；
- 保存按钮只在管理员登录且存在修改时可用。

当前保存接口采用最后一次写入覆盖策略，尚未实现多管理员并发版本冲突检测。

## 9. 数据安全和运维

### 9.1 不直接编辑 SQLite 文件

应通过后台编辑器或 API 修改避雨路网，不应直接编辑 `static.db` 的 WAL 文件或手工改写数据库。

### 9.2 备份和完整性

修改静态数据库前应：

1. 确认没有旧服务实例并行写库；
2. 使用 SQLite online backup；
3. 对备份执行 `PRAGMA quick_check`；
4. 在事务中写入；
5. 必要时执行 WAL checkpoint；
6. 再检查数据库完整性。

### 9.3 静态数据库与 Git

`static.db` 是地图静态数据的一部分，可以由 Git 跟踪。管理员保存避雨路网后，数据库会产生工作区修改；提交前应确认：

```bash
git status --short server/static.db
git diff --check
```

动态数据库、旧数据库、日志和临时备份不应随意提交。

## 10. 当前限制

1. 避雨路网是完整栅格副本，保存时提交整个 `rows`，不是增量补丁；
2. 没有自动判断哪些格子有雨棚，路径是否适合避雨完全由管理员编辑；
3. 当前 8 邻接规则允许部分对角线切角，避雨路网也沿用此行为；
4. 删除格子可能导致建筑入口、地下连接点或区域不可达，保存前尚未提供完整的全图连通性分析；
5. 多个管理员同时编辑时，后保存者可能覆盖先保存者；
6. 避雨版本主要通过 API 获取，服务端不可用时前台会退回普通路网；
7. 地下路线仍受现有一次进入、一次退出的集成算法限制。

## 11. 测试重点

应覆盖以下行为：

- 普通路网和避雨路网的坐标参数一致；
- 非法行数、列数、字符不能保存；
- 未登录不能保存；
- 没有避雨版本时前台开关不可用；
- 保存避雨版本后前台可以加载；
- 切换避雨模式会重新计算路线；
- 路网显示与当前寻路版本同步；
- 关闭避雨模式后恢复普通路线；
- 撤销、重做和放弃修改保持栅格一致；
- 保存不修改普通路网和地下路网。

当前实现的服务端、前台和构建测试均已通过；后续如果增加连通性检查或并发控制，应同步扩展本设计文档。
